# 生产提示词

本文件是项目各生产阶段直接使用的提示词真源。执行某一阶段时，读取对应章节，用当前项目的真实输入替换占位符，并把实际使用的提示词实例保存到项目 `prompts/` 目录。不得只转述章节原则而跳过提示词实例，也不得依赖本仓库之外的说明文件。

提示词仍受当前用户请求、`SKILL.md`、项目真源、可用工具和权限边界约束。本项目以用户提供的 SRT 与对应音频为时间真源，不在本流程内重新配音或重新做声学对齐。

| prompt_id | 使用阶段 | 必须产生的记录 |
|---|---|---|
| `visual-plan-v1` | 全片视觉编排 | `planning/visual-plan.json/.md` |
| `character-turnaround-v1` | 单图角色规范化 | `prompts/character/` 下的提示词实例与角色规范 |
| `a-roll-image-v1` | A-roll 画面生成 | `prompts/a-scenes/<shot-id>.json/.md` |
| `a-roll-view-v1` | A-roll 视角落实 | 同一 A-roll 镜头提示词实例中的视角记录 |
| `a-roll-action-sequence-v1` | A-roll 动作序列设计 | 同一 A-roll 镜头提示词实例中的 `action_sequence` 与动作状态资产 |
| `b-roll-motion-selection-v1` | B-roll 动效选择 | `prompts/b-scenes/<shot-id>.json/.md` 与逐镜选择结果 |

## 1. 视觉编排表

`prompt_id: visual-plan-v1`

```Markdown
帮我基于口播文案和已经提供的 SRT 时间轴，站在导演视角，产出一份可以直接指导剪辑、素材准备和动画制作的视觉编排表。

## 我提供的内容

- 口播文案：
【粘贴文案】

- SRT 时间轴：
【填入 source.srt 路径，或填入预检后保留原文的 cue 列表；每项包含开始时间、结束时间和对应文字】

## 编排原则

先理解整篇文案的逻辑，再把它拆成完整的语义段落。不要按标点、句子长度或每次停顿机械切镜。

每个镜头都要先回答：

1. 这一段最需要观众理解什么？
2. 什么画面能让这句话变得更具体、更容易理解？
3. 画面中的主体要发生什么变化？
4. 镜头最后停留在什么结果上？
5. 它如何承接上一镜，并自然进入下一镜？

## 画面类型

根据内容选择最合适的表达方式：

- 人物画面：适合情绪、经历、态度和个人表达；
- 场景画面：适合还原具体情境、动作和使用过程；
- 真实素材：适合证据、案例、产品、界面和操作展示；
- 信息图形：适合步骤、关系、比较、流程、数据和因果；
- 文字动效：适合金句、关键词、概念替换和结论强调。

不要为了丰富而频繁切换画面。每次变化都必须帮助观众理解内容。

如果文案提到真实产品、界面、数据、案例或用户素材，但我没有提供相应内容，请标记“需要补充素材”，不要自行编造。

## 时间与节奏

时间以我提供的 SRT 时间轴为准，不要自行估算，不要修改时间戳。

每个镜头的起止时间必须落在时间轴的短语边界上，不能跨语义切开。

镜头时长较长时，需要安排与旁白对应的内部变化，例如：

- 主体出现；
- 重点被选中或放大；
- 两个方案形成对比；
- 步骤逐项展开；
- 信息从混乱变得清晰；
- 最终结论落定。

入场、呼吸动画、背景循环和字幕出现不算有效的信息变化。避免画面长时间没有新内容，也不要让动画为了动而动。

## 输出格式

请使用以下表格：

| 镜头 | 时间 | 配音文案 | 画面类型 | 画面设计 | 动态变化 | 画面衔接 |
|---|---|---|---|---|---|---|

填写要求：

- 镜头：从 S001 开始连续编号；
- 时间：填写开始与结束时间（毫秒），必须来自我提供的时间轴；
- 配音文案：保留对应原文，不要擅自改写；
- 画面类型：从人物、场景、真实素材、信息图形、文字动效中选择；
- 画面设计：说明主体、构图、景别、关键元素和最终画面；
- 动态变化：按照旁白顺序写清第一次、第二次和第三次变化；没有必要时不要强行凑数；
- 画面衔接：说明前后镜头如何通过主体、动作、方向、位置、颜色或意义自然接续，不要只写“淡入淡出”。

## 全片检查

完成表格后，再检查：

1. 画面是否真正帮助理解文案；
2. 是否存在连续重复、节奏单一的问题；
3. 是否有镜头变化太少或信息过载；
4. 是否使用了未经提供或无法核实的素材；
5. 重要信息是否得到足够的视觉强调；
6. 前后镜头是否连贯；
7. 哪些镜头需要我补充素材或做出选择。

最后单独列出：

- 需要补充的素材；
- 需要确认的视觉方向；
- 制作难度较高的镜头。

现在先生成视觉编排表，不要直接制作图片、动画或视频。
```

## 2. IP 角色三视图

`prompt_id: character-turnaround-v1`

```Markdown
我给你一张 IP 角色的参考图，帮我基于这张图生成一份规范化的角色三视图，用于后续保持形象一致。

## 参考图
[放入 IP 角色的参考图]

## 你要做的事
第一步，先仔细分析这张参考图，把角色的关键特征全部识别出来，包括：
- 五官细节：眼睛、鼻子、嘴巴的画法和位置关系
- 头身比例：几头身、身体各部位的相对比例
- 服饰配饰：头顶、身上有什么标志性元素
- 配色方案：主色、辅色，画出具体色号
- 笔画风格：线条的粗细、颜色、上色方式、有没有阴影
- 整体气质：比方说圆润可爱、简笔卡通、写实等

第二步，把上面这些特征清楚地列出来给我看，方便我后续在别的提示词里直接引用。

第三步，基于识别出来的特征，生成正面、侧面、背面三个角度的三视图。
- 同一张图里输出三个角度
- 三个角度必须是同一个角色，五官、比例、配色、笔画风格完全一致
- 白色背景，角色居中，三个角度之间留出间距
```

## 3. A-roll 画面

`prompt_id: a-roll-image-v1`

```Markdown
基于IP角色参考图和视觉编排表里的镜头信息，生成对应的 A-roll 画面。

## 参考图（都要严格参照）
[放入三视图]：角色形象以这张为准，五官、体型、头身比例完全按这张来
[放入场景图]：场景风格和背景层次以这张为准，简化程度、虚化程度都保持一致
[放入细节笔触图]：笔画的线条粗细、上色方式、整体风格以这张为准

## 视觉编排表镜头信息
[粘贴视觉编排表里对应镜头的这一整行，包含镜头号、时间、配音文案、画面设计、动态变化]

## 你要做的事
第一步，读懂视觉编排表里这个镜头的意图：这一段配音在讲什么、观众要理解什么、画面要传达什么情绪、用什么视角（主持人 / 主角 / 配角 / 第一人称）。

第二步，基于三张参考图，生成对应的 A-roll 画面。以下要求都要遵守：
- 角色本身以三视图为准，头身比例、五官、体型不允许自由发挥
- 场景以场景图为准，背景保持简化、虚化，人物在前、背景在后，有明显的前后层次感
- 笔画风格以细节笔触图为准，线条粗细、上色方式、笔触感觉完全一致
- 画面里的动作、道具、构图，要匹配视觉编排表描述的镜头意图
```

## 4. A-roll 多视角画面

`prompt_id: a-roll-view-v1`

```Markdown
基于IP角色参考图和视觉编排表里的镜头信息，生成对应视角的 A-roll 画面。

## 参考图（都要严格参照）
[放入三视图]：角色形象以这张为准，五官、体型、头身比例完全按这张来
[放入场景图]：场景风格和背景层次以这张为准
[放入细节笔触图]：笔画的线条粗细、上色方式、整体风格以这张为准

## 视觉编排表镜头信息
[粘贴视觉编排表里对应镜头的这一整行，包含镜头号、时间、配音、画面设计、动态变化]

## 我想要的视角
[从下面四种里选一种，只选一种]：主持人视角 / 主角视角 / 配角视角 / 第一人称视角

## 四种视角的构图规范

### 主持人视角
- IP 角色正对镜头，居中站位
- 景别用中景到近景（腰部或胸部以上）
- 眼神看向镜头，跟观众对话的感觉
- 背景保持简化虚化，突出人物
- 适用：开场、章节过渡、总结陈词

### 主角视角
- IP 角色是画面主体，在场景里做动作或表现情绪
- 景别用全景或中景，能看到角色和它所在的环境
- 视线跟着动作走，不看镜头
- 背景要有具体的场景元素，跟场景图保持一致的层次感
- 适用：讲个人经历、演示动作、表达情绪、跟配角有互动

### 配角视角
- 画面主体不是 IP 角色，而是新增的一个配角形象
- IP 角色可以在画面里但不是焦点，也可以不出现
- 通过配角的动作或表情，补充说明主线内容
- 配角的画风必须跟三视图和细节图保持完全一致
- 适用：需要旁观视角补充、场景里有多个主体的时候

### 第一人称视角
- 画面就是 IP 角色眼睛里看到的东西
- 画面里通常看不到 IP 自己，或者只能看到手、脚这些局部
- 镜头有明确的方向感，像真的在看某样东西
- 适用：强调“我看到了什么”、进入某个新场景、观察某个具体对象

## 你要做的事
第一步，读懂视觉编排表里这段镜头的意图：这段配音在讲什么、观众要理解什么、情绪是什么。

第二步，按照我选定的视角类型的构图规范，规划画面：用什么景别、角色在画面哪个位置、视线看哪里、背景怎么处理。

第三步，保证画面里的角色、场景、笔触，跟三张参考图完全一致（头身比例、笔画风格、背景层次都不能自由发挥）。
```

## 5. A-roll 动作序列

`prompt_id: a-roll-action-sequence-v1`

```Markdown
基于这个 A-roll 镜头的原始旁白、准确时间边界、视觉编排和人物规范，设计并落实一个由旁白驱动的动作序列。不要把长镜头退化为一张静态图加缓慢推镜。

## 镜头输入

- 镜头号：【填入】
- 开始时间：【填入毫秒】
- 结束时间：【填入毫秒】
- 原始旁白：【逐字填入】
- 观众要理解或感受到什么：【填入】
- A-roll 视角：【主持人 / 主角 / 配角 / 第一人称】
- 视觉编排中的动态变化：【完整填入】
- 旁白节拍：【逐项填入 trigger_text、at_ms、information_change、state_after】
- 人物与视觉参考：【填入已经核实的参考图和规范】

## 你要做的事

第一步，判断这个镜头需要哪种实现：

- `single-state`：只允许用于 4000ms 以下、一个原子动作就能完整表达的镜头；必须解释为什么静止足够。
- `state-sequence`：用多张保持人物一致的状态图表现起始、发展和结果。
- `continuous-motion`：使用一条真实连续动画或可复现的分层动画，并能在不同时间点检查状态。

第二步，按照旁白顺序拆出动作节拍：

- 4000ms 以下至少 1 个状态；
- 4000ms 到 5999ms 至少 2 个状态；
- 6000ms 及以上至少 3 个状态。

每个状态必须填写：发生时间、触发短语、人物或主体发生的可见变化、变化后的画面状态、准备采用的实现方式。动作、道具、视线、人物与环境关系或景别变化必须帮助理解或感受；呼吸、眨眼、背景循环、字幕出现和单纯推拉不算有效状态。

第三步，落实资产：

- `state-sequence` 的每个状态必须有不同的状态资产，人物身份、场景空间和关键道具保持连续；
- `continuous-motion` 可以共用一个动画文件，但每个状态必须记录不同的证据时间点；
- 最后一状态必须与视觉编排的 `final_state` 一致，并能自然承接下一镜；
- 需要真实动作或真实道具但没有素材时，标记“需要补充素材”，不要伪造。

## 输出

把结果写入该镜头提示词实例的 `action_sequence`：

~~~json
{
  "mode": "state-sequence",
  "static_reason": null,
  "beats": [
    {
      "beat_id": "A01",
      "at_ms": 0,
      "trigger_text": "",
      "visual_state": "",
      "implementation": "generated-state-frame",
      "evidence": {
        "artifact": "",
        "artifact_time_ms": null
      }
    }
  ]
}
~~~

准备阶段可以暂不填写 `evidence`。生产完成后，每个状态都必须补上可定位的资产；连续动画还要填写该资产中的毫秒时间点。
```

## 6. B-roll 动效选择

`prompt_id: b-roll-motion-selection-v1`

```Markdown
帮我为这个 B-roll 镜头挑一个合适的动效。

## 镜头信息

- 镜头号：【填入镜头号】
- 时长：【填入毫秒】
- 配音内容：【填入这段配音】
- 观众要理解的一句话：【填入】
- B-roll 类型：【有素材 / 无素材 / 纯文字】
- 语义结构：【对比 / 聚合 / 筛选 / 层级 / 因果 / 替换 / 展开】
- 旁白节拍：【逐项填入 cue_ids、trigger_text、at_ms、information_change、state_after】
- 项目工具约束与可用环境：【填入用户明确指定、已验证镜头框架及当前运行条件；新制作默认 HyperFrames】

## 素材来源（按优先级）

- 本地样例模板库：【填入本地模板库路径，比方说 templates/broll/】
- 开源项目 1：https://github.com/heygen-com/hyperframes-launches
- 开源项目 2：https://github.com/Vincentwei1021/video-shotcraft

## 你要做的事

第一步，先去本地样例模板库里查找候选，检查实际预览、源码、语义关系、视觉风格及旁白节拍适配。选择器结果只是推荐，不能因为语义标签命中就认定只需替换文案。

第二步，如果本地样例模板里没有合适的，再按当前语义结构读取已登记开源项目中的具体候选，逐镜选出一个适配的动效。每镜记录唯一来源及其元素关系、主要动作、阶段顺序，不能综合多个来源；审核方式见本节末尾。

第三步，选定动效之后，只做最小修改让它匹配我们的 UI 规范：【背景色、锚点色、字体、其他个性化元素】。

实现前读取 `references/broll-runtime-selection.md`，把制作工具和决策写入视觉计划的 `production.primary_tool` 与 `production.runtime_decision`。成熟效果优先在其原框架制作；需要新制作时默认 HyperFrames；两者效果和成本相近时优先 HyperFrames。只有用户指定或存在可验证收益时才移植。报告选定工具、来源、适配理由、另一方案未采用的原因与证据，不能仅用个人熟悉程度或框架名称作决定。

第四步，把选定骨架的动作阶段逐项绑定到旁白节拍。`at_ms` 和 `trigger_text` 必须原样继承视觉计划；每个节拍写清此刻新增了什么信息、画面变成什么状态，以及实现方式。入场、背景循环、字幕出现、单纯淡入和尾部阅读保持不算旁白节拍。

## 输出

除模板选择结果外，把落实方案写入同一提示词实例的 `motion_sequence`：

~~~json
{
  "mode": "continuous-motion",
  "static_reason": null,
  "beats": [
    {
      "beat_id": "B01",
      "at_ms": 0,
      "trigger_text": "",
      "visual_state": "",
      "implementation": "rendered-motion",
      "evidence": {
        "artifact": "",
        "artifact_time_ms": 0
      }
    }
  ]
}
~~~

准备阶段可以暂不填写 `evidence`。生产完成后，状态序列的每个节拍使用不同资产；`continuous-motion` 和 `text-motion` 可以共用渲染文件，但每个节拍必须使用不同的文件内证据时间点。所有节拍还必须在 `reports/timeline-audit.json` 中映射到实际主时间线 item；只有渲染文件而没有时间线实例不算落实。

先记录选中的模板或动效、修改方案和检查结果。`review_mode=manual` 时交给用户确认后实现；用户已授权 `continuous` 时，完成同一检查并记录代理审核来源后继续，不为每镜重复暂停。
```

## 使用规则

1. 每个生产阶段读取并实际使用对应章节；不要只把章节改写成另一份原则说明。
2. 已有 SRT + MP3 时，直接进入预检，不要无故重新配音。
3. B-roll 先匹配本地模板；本地无匹配时再读取外部仓库。
4. 外部仓库必须落到具体子目录、镜头卡或 composition，不能只返回仓库首页。
5. `hyperframes-launches` 在许可证未确认前只能做结构研究和重新实现。
6. `video-shotcraft` 原生是 Remotion；合格效果可以直接在 Remotion 中改造并渲染，再导入 ChatCut。是否移植由逐镜 `runtime_decision` 决定，不能因为其他镜头使用 HyperFrames 就强制移植。
7. 按项目审核模式执行 §6 末尾的确认或自检；通过后实现、渲染并导入所选主时间线，保留选择记录。连续执行不扩大计费、账户或发布授权。
