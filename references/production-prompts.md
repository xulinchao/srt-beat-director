# 生产提示词

本文件是项目各生产阶段直接使用的提示词真源。执行某一阶段时，读取对应章节，用当前项目的真实输入替换占位符，并把实际使用的提示词实例保存到项目 `prompts/` 目录。不得只转述章节原则而跳过提示词实例，也不得依赖本仓库之外的说明文件。

提示词仍受当前用户请求、`SKILL.md`、项目真源、可用工具和权限边界约束。本项目以用户提供的 SRT 与对应音频为时间真源，不在本流程内重新配音或重新做声学对齐。

| prompt_id | 使用阶段 | 必须产生的记录 |
|---|---|---|
| `visual-plan-v1` | 全片视觉编排 | `planning/visual-plan.json/.md` |
| `character-turnaround-v1` | 单图角色规范化 | `prompts/character/` 下的提示词实例与角色规范 |
| `a-roll-image-v1` | A-roll 画面生成 | `prompts/a-scenes/<shot-id>.json/.md` |
| `a-roll-view-v1` | A-roll 视角落实 | 同一 A-roll 镜头提示词实例中的视角记录 |
| `a-roll-action-sequence-v1` | A-roll 动作序列设计 | 同一 A-roll 镜头提示词实例中的 `action_sequence` 与动作状态资产 |
| `b-roll-motion-selection-v1` | B-roll 动效选择 | `prompts/b-scenes/<shot-id>.json/.md` 与逐镜选择结果 |

## 1. 视觉编排表

`prompt_id: visual-plan-v1`

```Markdown
当前设计输入：【展开同一 design_ref 对应的版本、字体/色彩/安全区/画法/动作规则，以及本镜角色职责；规划未定时注明草稿，生产不可缺省。实例根节点保存 design_ref。身份仍以授权 reference index 为准。】

帮我基于口播文案和已经提供的 SRT 时间轴，站在导演视角，产出一份可以直接指导剪辑、素材准备和动画制作的视觉编排表。

## 我提供的内容

- 口播文案：
【粘贴文案】

- SRT 时间轴：
【填入 source.srt 路径，或填入预检后保留原文的 cue 列表；每项包含开始时间、结束时间和对应文字】

## 编排原则

读取 design-system.md。先从文案理解点确定 A/B 叙事职责，再按功能、主体关系、载体、必要动作和本片风格编排，填写 visual_design.function/relation/carrier/character_role；复杂互动才填写 interaction，时间引用 narration_beats。每镜在 `visual_design.motion_intent` 写清连续动作、定格状态切换、程序化动效或静止及其旁白触发、停留和转变节奏，随后在 `production.primary_tool` 写明制作工具与选择依据。MiniMax H3、HyperFrames、Remotion 均可用于 A/B，不能按工具、人物是否出现或素材是否生成来划分职责。选用 H3 时按对应模式登记首尾帧或参考图、workflow 与运动提示。不预设配色或交替比例；画风由本片 DESIGN 决定。用户未明确要求 IP 时不创造固定 IP；已要求 IP 时先确认其是否参与 B-roll，不能因为存在 IP 就让它占据每个信息镜头。

知识分享与读书稿先使用 knowledge-reading-direction.md：区分问题、观点、引文、解释、案例、实践和总结；A-roll 先设计人物处境，B-roll 先确定内容关系。读书稿明确作者原话、转述与个人理解的归属，不伪造原文或经历。

先理解整篇文案的逻辑，再把它拆成完整的语义段落。不要按标点、句子长度或每次停顿机械切镜。

每个镜头都要先回答：

1. 这一段最需要观众理解什么？
2. 什么画面能让这句话变得更具体、更容易理解？
3. 画面中的主体要发生什么变化？
4. 镜头最后停留在什么结果上？
5. 它如何承接上一镜，并自然进入下一镜？

每个 B-roll 语义段还要确定一个具体视觉结构，写清空间关系、阅读路径和核心动作，例如文档组装、问题雷达、经历桥、判断天平或学习循环。统一全片的配色、字体、材质和标注系统，但不要把不同内容都塞进同一种列表、三卡或左右分栏。

选择当前 B-roll 前，对照最近三个 B-roll，判断复用是否帮助解释。允许同一核心图逐段发展、同维度案例比较和结尾回顾；记录语义理由与新增内容或回顾用途，不强制换布局。机械换字换色不能冒充新的解释。

## 画面类型

根据内容选择最合适的表达方式：

- 人物画面：适合情绪、经历、态度和个人表达；
- 场景画面：适合还原具体情境、动作和使用过程；
- 真实素材：适合证据、案例、产品、界面和操作展示；
- 信息图形：适合步骤、关系、比较、流程、数据和因果；
- 文字动效：适合金句、关键词、概念替换和结论强调。

不要为了丰富而频繁切换画面。每次变化都必须帮助观众理解内容。

如果文案提到真实产品、界面、数据、案例或用户素材，但我没有提供相应内容，请标记“需要补充素材”，不要自行编造。

## 时间与节奏

时间以我提供的 SRT 时间轴为准，不要自行估算，不要修改时间戳。

每个镜头的起止时间必须落在时间轴的短语边界上，不能跨语义切开。

镜头时长较长时，需要安排与旁白对应的内部变化，例如：

- 主体出现；
- 重点被选中或放大；
- 两个方案形成对比；
- 步骤逐项展开；
- 信息从混乱变得清晰；
- 最终结论落定。

入场、呼吸动画、背景循环和字幕出现不算有效的信息变化。避免画面长时间没有新内容，也不要让动画为了动而动。

按 sound-design.md 判断关键动作是否需要简单音效。碰撞、落地、启动、盖章等动作按需注明声音意图，写入对应 changes[].event 并同步 narration_beats 的状态描述，在七列表格的“动态变化”中呈现；素材需求写入 materials。精确起音待实际动作确定后对齐接触或落定帧，不新增旁白节拍，不移动 SRT。不要每次文字出现都配声；BGM 与复杂声音设计仍按用户要求添加。

## 输出格式

请使用以下表格：

| 镜头 | 时间 | 配音文案 | 画面类型 | 画面设计 | 动态变化 | 画面衔接 |
|---|---|---|---|---|---|---|

填写要求：

- 镜头：从 S001 开始连续编号；
- 时间：填写开始与结束时间（毫秒），必须来自我提供的时间轴；
- 配音文案：保留对应原文，不要擅自改写；
- 画面类型：从人物、场景、真实素材、信息图形、文字动效中选择；
- 画面设计：说明主体、构图、景别、关键元素和最终画面；
- 动态变化：按照旁白顺序写清第一次、第二次和第三次变化；没有必要时不要强行凑数；
- 画面衔接：说明前后镜头如何通过主体、动作、方向、位置、颜色或意义自然接续，不要只写“淡入淡出”。

七列表格后必须增加“逐镜制作路由”表，逐镜列出 A/B、`motion_intent`、`production.primary_tool` 和工具决策/辅助链路；保持七列表头不变。ChatCut 是完整视频的主工程，不能把 HyperFrames/Remotion 的单镜制作工具误写成整片主工程。

## 全片检查

完成表格后，再检查：

1. 画面是否真正帮助理解文案；
2. 是否存在连续重复、节奏单一的问题；
3. 对照近邻和跨段核心图，复用是否帮助递进、比较或回顾；是否存在无解释收益的机械换字换色；
4. 是否有镜头变化太少或信息过载；
5. 是否使用了未经提供或无法核实的素材；
6. 重要信息是否得到足够的视觉强调；
7. 前后镜头是否连贯；
8. 哪些镜头需要我补充素材或做出选择。

最后单独列出：

- 需要补充的素材；
- 需要确认的视觉方向；
- 制作难度较高的镜头。

现在先生成视觉编排表，不要直接制作图片、动画或视频。
```

```Markdown
## 四种视角的构图规范

### 主持人视角
- 本镜主持人物正对镜头，居中站位；有获准 IP 时才使用该 IP
- 景别用中景到近景（腰部或胸部以上）
- 眼神看向镜头，跟观众对话的感觉
- 背景保持简化虚化，突出人物

### 主角视角
- 本镜主角是画面主体，在场景里做动作或表现情绪
- 景别用全景或中景，能看到角色和它所在的环境
- 视线跟着动作走，不看镜头

### 配角视角

- 已获准的 IP 可在画面里但不是焦点，也可以不出现；未启用 IP 时不补一个进去

### 第一人称视角
- 画面是本镜第一人称人物眼睛里看到的东西
- 画面里通常看不到该人物，或者只能看到手、脚这些局部
- 镜头有明确的方向感，像真的在看某样东西
- 适用：强调“我看到了什么”、进入某个新场景、观察某个具体对象

## 你要做的事
```

## 5. A-roll 动作序列

`prompt_id: a-roll-action-sequence-v1`

```Markdown
当前设计输入：【展开同一 design_ref 对应的版本、字体/色彩/安全区/画法/动作规则，以及本镜角色职责；规划未定时注明草稿，生产不可缺省。实例根节点保存 design_ref。身份仍以授权 reference index 为准。】

基于这个 A-roll 镜头的原始旁白、准确时间边界、视觉编排和人物规范，设计并落实一个由旁白驱动的动作序列。不要把长镜头退化为一张静态图加缓慢推镜。

## 镜头输入

- 镜头号：【填入】
- 开始时间：【填入毫秒】
- 结束时间：【填入毫秒】
- 原始旁白：【逐字填入】
- 观众要理解或感受到什么：【填入】
- A-roll 视角：【主持人 / 主角 / 配角 / 第一人称】
- 视觉编排中的动态变化：【完整填入】
- 旁白节拍：【逐项填入 trigger_text、at_ms、information_change、state_after】
- 人物与视觉参考：【填入已经核实的参考图和规范】

## 你要做的事

第一步，判断这个镜头需要哪种实现：

- `single-state`：一个状态足以表达的镜头，不限制秒数；计划仅一个节拍，继承 shot.static_reason，说明静止期间旁白为何仍与画面对应。
- `state-sequence`：用多张状态图表现起始、发展和结果；若设计为定格动画，明确每张图的停留与跳变节奏，不要求插帧成自然连续动作。
- `continuous-motion`：使用一条真实连续动画或可复现的分层动画，并能在不同时间点检查状态。人物/场景需要自然连续运动时才评估 ComfyUI 视频工作流。

第二步，按照旁白顺序拆出动作节拍：

- 至少落实一个语义状态；单状态实现必须继承计划 static_reason。
- 状态数量由旁白的真实变化决定，不按秒数凑图。
- 多个计划节拍必须全部落实，不能用静止理由删减；保持阶段不伪造新的节拍。

每个状态必须填写：发生时间、触发短语、人物或主体发生的可见变化、变化后的画面状态、准备采用的实现方式。动作、道具、视线、人物与环境关系或景别变化必须帮助理解或感受；呼吸、眨眼、背景循环、字幕出现和单纯推拉不算有效状态。

第三步，落实资产：

- `state-sequence` 的每个状态必须有不同的状态资产，人物身份、场景空间和关键道具保持连续；
- `continuous-motion` 可以共用一个动画文件，但每个状态必须记录不同的证据时间点；
- 最后一状态必须与视觉编排的 `final_state` 一致，并能自然承接下一镜；
```

## 使用规则

1. 每个生产阶段读取并实际使用对应章节；不要只把章节改写成另一份原则说明。
2. 已有 SRT + MP3 时，直接进入预检，不要无故重新配音。
3. B-roll 先匹配本地模板；本地无匹配时再读取外部仓库。
4. 外部仓库必须落到具体子目录、镜头卡或 composition，不能只返回仓库首页。
5. `hyperframes-launches` 在许可证未确认前只能做结构研究和重新实现。
6. `video-shotcraft` 原生是 Remotion；合格效果可以直接在 Remotion 中改造并渲染，再导入 ChatCut。是否移植由逐镜 `runtime_decision` 决定，不能因为其他镜头使用 HyperFrames 就强制移植。
7. 按项目审核模式执行 §6 末尾的确认或自检；通过后实现、渲染并导入所选主时间线，保留选择记录。连续执行不扩大计费、账户或发布授权。
8. 每次实例化至少记录 `prompt_id`、本文件 SHA-256、镜头 ID 或阶段 ID、代入的项目输入、最终提示词、输出资产和执行状态；没有实例记录，不能声称该提示词已使用。
9. 每个 A-roll 都必须运行 `a-roll-action-sequence-v1`。不能以已有单张图、ChatCut Slow Push、呼吸或眨眼效果代替动作序列判断。
10. 每个 B-roll 都必须把选型结果落实成 `motion_sequence`。不能以模板链接、终态截图或存在于本地但未进入主时间线的渲染文件冒充完成。
