# 生产提示词

本文件是项目各生产阶段直接使用的提示词真源。执行某一阶段时，读取对应章节，用当前项目的真实输入替换占位符，并把实际使用的提示词实例保存到项目 `prompts/` 目录。不得只转述章节原则而跳过提示词实例，也不得依赖本仓库之外的说明文件。

提示词仍受当前用户请求、`SKILL.md`、项目真源、可用工具和权限边界约束。本项目以用户提供的 SRT 与对应音频为时间真源，不在本流程内重新配音或重新做声学对齐。

| prompt_id | 使用阶段 | 必须产生的记录 |
|---|---|---|
| `visual-plan-v1` | 全片视觉编排 | `planning/visual-plan.json/.md` |
| `character-turnaround-v1` | 单图角色规范化 | `prompts/character/` 下的提示词实例与角色规范 |
| `a-roll-image-v1` | A-roll 画面生成 | `prompts/a-scenes/<shot-id>.json/.md` |
| `a-roll-view-v1` | A-roll 视角落实 | 同一 A-roll 镜头提示词实例中的视角记录 |
| `a-roll-action-sequence-v1` | A-roll 动作序列设计 | 同一 A-roll 镜头提示词实例中的 `action_sequence` 与动作状态资产 |
| `b-roll-motion-selection-v1` | B-roll 动效选择 | `prompts/b-scenes/<shot-id>.json/.md` 与逐镜选择结果 |

## 1. 视觉编排表

`prompt_id: visual-plan-v1`

```Markdown
当前设计输入：【展开同一 design_ref 对应的版本、字体/色彩/安全区/画法/动作规则，以及本镜角色职责；规划未定时注明草稿，生产不可缺省。实例根节点保存 design_ref。身份仍以授权 reference index 为准。】

帮我基于口播文案和已经提供的 SRT 时间轴，站在导演视角，产出一份可以直接指导剪辑、素材准备和动画制作的视觉编排表。

## 我提供的内容

- 流程配置：【从当前project.json展开primary_timeline、sequence_review_policy、样片区间和review_mode；保留实际用户授权，不推断独立HyperFrames整片例外。】

- 口播文案：
【粘贴文案】

- SRT 时间轴：
【填入 source.srt 路径，或填入预检后保留原文的 cue 列表；每项包含开始时间、结束时间和对应文字】

## 编排原则

新任务在计划根节点声明 motion_review_policy=evidence-first-v1，按本片实际高风险动作和信息密度选择 baseline_shot_ids，不为凑A/B各一镜增添内容。每镜 visual_design.motion_mode 选择实际运动方式；非静止镜头用 motion_check 写明谁对什么做什么、可见结果和必要状态（contracts §10）。一个旁白节拍可以包含多个动作状态，不因cue少改成静止，不增造旁白时间点。单张画风预览与动作状态验证分开交付，未覆盖必要状态不能作为动作基线。

读取 design-system.md。先从文案理解点确定 A/B 叙事职责，再按功能、主体关系、载体、必要动作和本片风格编排，填写 visual_design.function/relation/carrier/character_role；复杂互动才填写 interaction，时间引用 narration_beats。每镜在 `visual_design.motion_intent` 写清连续动作、定格状态切换、程序化动效或静止及其旁白触发、停留和转变节奏，随后在 `production.primary_tool` 写明制作工具与选择依据。MiniMax H3、HyperFrames、Remotion 均可用于 A/B，不能按工具、人物是否出现或素材是否生成来划分职责。选用 H3 时按对应模式登记首尾帧或参考图、workflow 与运动提示。不预设配色或交替比例；画风由本片 DESIGN 决定。用户未明确要求 IP 时不创造固定 IP；已要求 IP 时先确认其是否参与 B-roll，不能因为存在 IP 就让它占据每个信息镜头。

配置启用sequence-quality-v1时读取sequence-quality.md，先定义整片观看过程，在计划根填写sequence_direction的visual_thread、continuity、layout_rules、motion_language；每镜production.assembly_tool与主工程一致。非静止程序化镜头或custom_motion=true的镜头声明motion_reference_review，实际制作前看真实候选并记录适配，不因照片有素材或scene分类免除。区分解释性对象变化与装饰入场，必要阅读保留静止；选择能连看相邻镜头的样片，在运动中间态、接缝及整体PPT感通过内部检查后再扩大制作，不用完整候选豁免质量门。

知识分享与读书稿先使用 knowledge-reading-direction.md：区分问题、观点、引文、解释、案例、实践和总结；A-roll 先设计人物处境，B-roll 先确定内容关系。读书稿明确作者原话、转述与个人理解的归属，不伪造原文或经历。

先理解整篇文案的逻辑，再把它拆成完整的语义段落。不要按标点、句子长度或每次停顿机械切镜。

每个镜头都要先回答：

1. 这一段最需要观众理解什么？
2. 什么画面能让这句话变得更具体、更容易理解？
3. 画面中的主体要发生什么变化？
4. 镜头最后停留在什么结果上？
5. 它如何承接上一镜，并自然进入下一镜？

每个 B-roll 语义段还要确定一个具体视觉结构，写清空间关系、阅读路径和核心动作，例如文档组装、问题雷达、经历桥、判断天平或学习循环。新编排在计划根节点写 broll_matching_policy=expression-first-v1 与 broll_layout_policy=motion-first-v1，程序化 B-roll 按 broll-expression-selection.md 保存动作简报，不按题材关键词直接选模板。统一全片的配色、字体、素材笔触与细节精度、主体比例、文字层级和标注系统，但不要把不同内容都塞进同一种列表、三卡或左右分栏。

选择当前 B-roll 前，对照最近三个 B-roll，判断复用是否帮助解释。允许同一核心图逐段发展、同维度案例比较和结尾回顾；记录语义理由与新增内容或回顾用途，不强制换布局。机械换字换色不能冒充新的解释。

按 directing.md 的“表达方式与元素选择”先判断图解、IP 互动讲解、人物叙事或证据展示的解释收益。并列三项可直接用三张卡片；比较、筛选和流程再按关系设计变化，不为增加动画而加入人物。需要 IP 互动讲解时，写清它对什么做什么、让观众看见什么关系，再选必要载体与动作机制。隐喻不能新增事实或错误因果。准备、行动、对象反应、后果和保持按需要组合，只细化现有 changes 与 narration_beats，不固定秒数或增加语义节拍。静止、定格与连续运动按内容和 DESIGN 选择；候选方法仍需实际短片验证。

## 画面类型

根据内容选择最合适的表达方式：

- 人物画面：适合情绪、经历、态度和个人表达；
- 场景画面：适合还原具体情境、动作和使用过程；
- 真实素材：适合证据、案例、产品、界面和操作展示；
- 信息图形：适合步骤、关系、比较、流程、数据和因果；
- 文字动效：适合金句、关键词、概念替换和结论强调。

不要为了丰富而频繁切换画面。每次变化都必须帮助观众理解内容。

如果文案提到真实产品、界面、数据、案例或用户素材，但我没有提供相应内容，请标记“需要补充素材”，不要自行编造。

## 时间与节奏

时间以我提供的 SRT 时间轴为准，不要自行估算，不要修改时间戳。

每个镜头的起止时间必须落在时间轴的短语边界上，不能跨语义切开。

镜头时长较长时，需要安排与旁白对应的内部变化，例如：

- 主体出现；
- 重点被选中或放大；
- 两个方案形成对比；
- 步骤逐项展开；
- 信息从混乱变得清晰；
- 最终结论落定。

入场、呼吸动画、背景循环和字幕出现不算有效的信息变化。避免画面长时间没有新内容，也不要让动画为了动而动。

按 sound-design.md 判断关键动作是否需要简单音效。碰撞、落地、启动、盖章等动作按需注明声音意图，写入对应 changes[].event 并同步 narration_beats 的状态描述，在七列表格的“动态变化”中呈现；素材需求写入 materials。精确起音待实际动作确定后对齐接触或落定帧，不新增旁白节拍，不移动 SRT。不要每次文字出现都配声；BGM 与复杂声音设计仍按用户要求添加。

## 输出格式

请使用以下表格：

| 镜头 | 时间 | 配音文案 | 画面类型 | 画面设计 | 动态变化 | 画面衔接 |
|---|---|---|---|---|---|---|

填写要求：

- 镜头：从 S001 开始连续编号；
- 时间：填写开始与结束时间（毫秒），必须来自我提供的时间轴；
- 配音文案：保留对应原文，不要擅自改写；
- 画面类型：从人物、场景、真实素材、信息图形、文字动效中选择；
- 画面设计：说明主体、构图、景别、关键元素和最终画面；
- 动态变化：按照旁白顺序写清第一次、第二次和第三次变化；没有必要时不要强行凑数；
- 画面衔接：说明前后镜头如何通过主体、动作、方向、位置、颜色或意义自然接续，不要只写“淡入淡出”。

七列表格后必须增加“逐镜制作路由”表，逐镜列出 A/B、`motion_intent`、`production.primary_tool` 和工具决策/辅助链路；保持七列表头不变。ChatCut 是完整视频的主工程，不能把 HyperFrames/Remotion 的单镜制作工具误写成整片主工程。

## 全片检查

完成表格后，再检查：

1. 画面是否真正帮助理解文案；
2. 是否存在连续重复、节奏单一的问题；
3. 对照近邻和跨段核心图，复用是否帮助递进、比较或回顾；是否存在无解释收益的机械换字换色；
4. 是否有镜头变化太少或信息过载；
5. 是否使用了未经提供或无法核实的素材；
6. 重要信息是否得到足够的视觉强调；
7. 前后镜头是否连贯；
8. 哪些镜头需要我补充素材或做出选择。

最后单独列出：

- 需要补充的素材；
- 需要确认的视觉方向；
- 制作难度较高的镜头。

现在先生成视觉编排表，不要直接制作图片、动画或视频。
```

## 4. A-roll 多视角画面

`prompt_id: a-roll-view-v1`

```Markdown
当前设计输入：【展开同一 design_ref 对应的版本、字体/色彩/安全区/画法/动作规则，以及本镜角色职责；规划未定时注明草稿，生产不可缺省。实例根节点保存 design_ref。身份仍以授权 reference index 为准。】

基于实际已核实的人物/场景参考和视觉编排表里的镜头信息，生成对应视角的 A-roll 画面。只有用户明确要求 IP 时才使用固定 IP 身份；普通剧情人物不自动成为 IP。

## 参考图（只填本项目实际存在且用途已授权的图）
[已核实的人物参考或三视图，如有]：重复人物的身份特征以此为准
[已核实的场景参考，如有]：场景空间与风格以此为准
[已核实的细节画法参考，如有]：笔触与材质以此为准

## 视觉编排表镜头信息
[粘贴视觉编排表里对应镜头的这一整行，包含镜头号、时间、配音、画面设计、动态变化]

## 我想要的视角
[从下面四种里选一种，只选一种]：主持人视角 / 主角视角 / 配角视角 / 第一人称视角

## 四种视角的构图规范

### 主持人视角
- 本镜主持人物正对镜头，居中站位；有获准 IP 时才使用该 IP
- 景别用中景到近景（腰部或胸部以上）
- 眼神看向镜头，跟观众对话的感觉
- 背景保持简化虚化，突出人物
- 适用：开场、章节过渡、总结陈词

### 主角视角
- 本镜主角是画面主体，在场景里做动作或表现情绪
- 景别用全景或中景，能看到角色和它所在的环境
- 视线跟着动作走，不看镜头
- 背景要有具体的场景元素，跟场景图保持一致的层次感
- 适用：讲个人经历、演示动作、表达情绪、跟配角有互动

### 配角视角
- 画面主体是配角，而不是主讲人物
- 已获准的 IP 可在画面里但不是焦点，也可以不出现；未启用 IP 时不补一个进去
- 通过配角的动作或表情，补充说明主线内容
- 配角的画风遵循已确认的视觉系统，不凭空套用不存在的三视图
- 适用：需要旁观视角补充、场景里有多个主体的时候

### 第一人称视角
- 画面是本镜第一人称人物眼睛里看到的东西
- 画面里通常看不到该人物，或者只能看到手、脚这些局部
- 镜头有明确的方向感，像真的在看某样东西
- 适用：强调“我看到了什么”、进入某个新场景、观察某个具体对象

## 你要做的事
第一步，读懂视觉编排表里这段镜头的意图：这段配音在讲什么、观众要理解什么、情绪是什么。

第二步，按照我选定的视角类型的构图规范，规划画面：用什么景别、角色在画面哪个位置、视线看哪里、背景怎么处理。

第三步，保证画面遵循实际已批准的人物身份、场景和画法参考；不存在的参考图不作为生产前提。
```

## 5. A-roll 动作序列

## 你要做的事

第一步，判断这个镜头需要哪种实现：

- `single-state`：一个状态足以表达的镜头，不限制秒数；计划仅一个节拍，继承 shot.static_reason，说明静止期间旁白为何仍与画面对应。
- `state-sequence`：用多张状态图表现起始、发展和结果；若设计为定格动画，明确每张图的停留与跳变节奏，不要求插帧成自然连续动作。
- `continuous-motion`：使用一条真实连续动画或可复现的分层动画，并能在不同时间点检查状态。人物/场景需要自然连续运动时才评估 ComfyUI 视频工作流。

第二步，按照旁白顺序拆出动作节拍：

旁白节拍与动作内部状态分开：同一句话可以有完整连续动作，不因 beats 只有一项改成 single-state。新计划按 contracts §10 声明 motion_review_policy=evidence-first-v1、baseline_shot_ids，以及每镜 visual_design.motion_mode；非静止镜头的 motion_check 写清动作、可见结果和必要状态，状态用 beat_index 引用已有旁白锚点，不新造 cue 时间。实例的 action_sequence/motion_sequence.mode 必须与计划一致。

- 至少落实一个语义状态；单状态实现必须继承计划 static_reason。
- 状态数量由旁白的真实变化决定，不按秒数凑图。
- 多个计划节拍必须全部落实，不能用静止理由删减；保持阶段不伪造新的节拍。

每个状态必须填写：发生时间、触发短语、人物或主体发生的可见变化、变化后的画面状态、准备采用的实现方式。动作、道具、视线、人物与环境关系或景别变化必须帮助理解或感受；呼吸、眨眼、背景循环、字幕出现和单纯推拉不算有效状态。

生成式连续动作在提交前按 comfyui-video-production.md 的“实际图片到动作提示词”检查采用图，写清已存在元素、具体操作、对象反应和结束停点。用实际图校准动作细节，不改变批准的语义；不支持原意时改图或复核计划。动作细节保存在现有 implementation 与运动提示中，不能把提示词中的秒数当作已实现的证据时间。

第三步，落实资产：

- `state-sequence` 的每个状态必须有不同的状态资产，人物身份、场景空间和关键道具保持连续；
- `continuous-motion` 可以共用一个动画文件，但每个状态必须记录不同的证据时间点；
- 最后一状态必须与视觉编排的 `final_state` 一致，并能自然承接下一镜；
- 需要真实动作或真实道具但没有素材时，标记“需要补充素材”，不要伪造。

## 使用规则

1. 每个生产阶段读取并实际使用对应章节；不要只把章节改写成另一份原则说明。
2. B-roll 先走快路径：匹配本地认证模板库，本地无匹配时再读取参考仓库源码并完成逐镜来源确认；只有召回结果但未确认适配，不算命中。转慢路径自建始终需要完整研究记录和扩大搜索证据。
3. 参考仓库必须落到具体子目录、镜头卡或 composition，不能只返回仓库首页。
4. 参考仓库效果直接在其原生框架渲染并导入 ChatCut；新制作的程序化动画默认 HyperFrames。不因其他镜头使用不同框架就强制移植。
5. 按运动方案选择静帧检查方式，按项目既有审核模式记录 layout_review；多状态镜头还需带原旁白动态预览，再渲染并导入所选主时间线。连续执行不扩大计费、账户或发布授权。
6. 每次实例化至少记录 `prompt_ids`（实际使用的提示词 ID 列表，与实例契约一致）、本文件 SHA-256、镜头 ID 或阶段 ID、代入的项目输入、最终提示词、输出资产和执行状态；没有实例记录，不能声称该提示词已使用。
7. 每个 A-roll 都必须运行 `a-roll-action-sequence-v1`。不能以已有单张图、ChatCut Slow Push、呼吸或眨眼效果代替动作序列判断。
8. 每个 B-roll 都必须把选型结果落实成 `motion_sequence`。不能以模板链接、终态截图或存在于本地但未进入主时间线的渲染文件冒充完成。
