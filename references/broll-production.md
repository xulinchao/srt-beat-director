# B-roll 制作契约

本文件把 `references/production-prompts.md` §6 的 B-roll 提示词转成可执行门控。它解决的核心问题是：B-roll 不能从“看起来像动效”开始，而要先确定观众理解点、语义结构和唯一的动效来源。

## 每镜头输入

- 镜头号、毫秒时长、逐字口播文案；
- 观众看完这一镜必须理解的一句话；
- B-roll 类型：`verified-media`、`no-material` 或 `text-only`；
- 一个主语义结构：`comparison`、`aggregation`、`filtering`、`hierarchy`、`causality`、`replacement`、`expansion`；
- 信息项数量、画幅、字幕安全区和真实性限制。

## 选型顺序

1. 先查本地模板库。存在合格模板时，只替换当前镜头需要的文案、素材和配置，不重写核心动作。
2. 本地没有合格模板时，把已登记的开源仓库当作候选池，读取具体镜头卡和实现文件。
3. 每个镜头只能选择一个 `selected_candidate`。另一个候选只能写在研究记录里，标记为 `partial` 或 `rejected` 并写明理由，不得把它的布局、节奏、easing 或阶段顺序带入实现。
4. 选定后先记录：元素关系、主要动作、阶段顺序、许可证、原框架、最小改造范围和实现方式；研究记录验证通过后才制作。

## 实现边界

“最小修改”只允许改变：

- 背景色、强调色、字体；
- 当前项目的文案、标签和已核实素材；
- 为适配画幅、安全区和时长所需的最小尺寸调整。

不得改变选定来源的核心运动语法。`port-required` 候选要以其实现文件为骨架移植；`structure-study-only` 候选只能按该单一骨架重实现；只有所有候选均不合适，且逐项记录拒绝理由后，才允许自建。

ChatCut JSX 是落地载体，不是动效来源。最终资产必须在描述和研究记录中绑定到一个具体镜头卡/实现文件；不能用“参考了两个项目”代替来源绑定。

## 四阶段动作要求

每个 B-roll 至少写出三个有效信息阶段，通常包括：

1. 建立主体或共同问题；
2. 发生关系变化、比较、筛选、连接或展开；
3. 重点被确认或结果成立；
4. 如时长允许，保留一个可读的定格结果。

入场淡化、背景循环、字幕出现和单纯镜头推拉不算有效阶段。

## 交付前检查

- 不看字幕，画面是否仍能读出关系或结论；
- 动画顺序是否跟随口播顺序；
- 是否连续重复、信息过载或长时间没有新信息；
- 是否使用未经提供或无法核实的真实素材；
- 是否只使用一个最终来源；
- 是否落档了镜头卡、实现文件、许可证、当前资产和时间线实例；
- 是否实际预览了入场、变化中段和最终定格帧。
