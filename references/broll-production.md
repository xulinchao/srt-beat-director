# B-roll 制作契约

本文件与 `references/production-prompts.md` §6 `b-roll-motion-selection-v1` 配套使用。§6 是每个 B-roll 必须实际实例化的选择提示词，本文件负责其数据约束、实现门控和验收。B-roll 不能从“看起来像动效”开始，而要先确定观众理解点、语义结构和唯一的动效来源。

每镜先保存 `prompts/b-scenes/<shot-id>.json/.md`，至少记录 `prompt_ids`（数组，与实例契约一致）、生产提示词文件 SHA-256、镜头输入、最终提示词、选择报告路径、输出资产和状态。缺少该记录时，即使模板选择或动画文件存在，也不能声称 §6 已使用。

## 每镜头输入

- 镜头号、毫秒时长、逐字口播文案；
- 观众看完这一镜必须理解的一句话；
- B-roll 类型：`verified-media`、`no-material` 或 `text-only`；
- 一个主语义结构：`comparison`、`aggregation`、`filtering`、`hierarchy`、`causality`、`replacement`、`expansion`；
- 一个具体视觉结构 `visual_structure`，说明主体的空间关系、阅读路径和核心动作；
- 最近三个 B-roll 的 `visual_structure`、`semantic_pattern`、模板与构图，用于选型前复用审查；
- 信息项数量、画幅、字幕安全区和真实性限制。

## 选型顺序

先区分表达载体：生成式解释场景使用 `no-material + scene`，按动作、参考素材和工具能力选择；精确图形/文字关系使用 `no-material + infographic`，再走下面的模板研究流程。生成场景不能标成真实证据，也不为满足模板字段编造代码来源。所有 B-roll 仍保存 `planning/template-selection/<shot-id>.json`：生成场景在该报告记录 `shot_id`、`design_ref`、`primary_tool`、选择理由和参考来源，`template_id` 可为 null；只有代码模板路径使用模板选择器和外部研究门。

先按计划选择运动形式：自然连续的人物/场景动作、刻意的定格状态切换或程序化信息动效。定格动画在 `visual_design.motion_intent` 写明每个状态的停留与跳变，`motion_sequence` 使用 `state-sequence` 并与旁白节拍逐项对应；不因使用多张状态图就自动调用 H3。需要首尾帧之间生成运动时，可按逐镜工具决策选择 MiniMax H3；本镜因解释内容而属于 B-roll，其他 H3 镜头仍按自身叙事职责分类。若用户明确要求 IP 且同意其参与 B-roll，仍按本段理解任务决定它是否出现及承担什么作用。

候选推荐不等于制作工具决策。选型时读取 [制作工具决策](broll-runtime-selection.md)，先检查表达、视觉、节拍与运行条件，再把 `runtime_decision` 写入镜头 `production`。合格来源可以在 HyperFrames 或 Remotion 原生制作，二者在 ChatCut 素材层汇合。

1. 先查本地模板库。存在合格模板时，只替换当前镜头需要的文案、素材和配置，不重写核心动作。
2. 本地没有合格模板时，把已登记的开源仓库当作候选池，读取具体镜头卡和实现文件。
3. 每个镜头只能选择一个 `selected_candidate`。另一个候选只能写在研究记录里，标记为 `partial` 或 `rejected` 并写明理由，不得把它的布局、节奏、easing 或阶段顺序带入实现。
4. 选定后先记录：元素关系、主要动作、阶段顺序、许可证、原框架、最小改造范围和实现方式；研究记录验证通过后才制作。
5. 对照最近三个 B-roll 做结构审计。允许同图递进、同维度比较和回顾，记录复用理由与内容推进或回顾用途；机械换字换色且无解释收益应返工，不为去重强制换布局。

## 实现边界

以上唯一来源约束适用于复用/移植。用头像替换进度标记且关系和动作阶段不变，可以作为素材适配；新增托举、接触、遮挡或连锁反应改变骨架时，明确拒绝不合适候选，按 custom-after-external-review 记录自建，不伪称最小修改。自建记录真实借鉴原则与源码来源，不受“必须映射一个外部实现文件”限制，仍不可拼接未授权代码。

选型报告保存与计划相同的 design_ref（选择器使用 `--visual-style <project>/config/visual-style.json`）。按主体、关系、变化检索，检查具体预览和源码、中文容量、内部节拍、DESIGN 兼容、许可证、依赖与实际渲染。文字和角色分层制作，复杂接触按 [design-system.md](design-system.md) 记录；不能为了绑定来源硬套效果。

复用路径的“最小修改”允许改变：

- 背景色、强调色、字体；
- 当前项目的文案、标签和已核实素材；
- 为适配画幅、安全区和时长所需的最小尺寸调整。

不得改变选定来源的核心运动语法。`port-required` 表示旧目录尚未提供可直接复用的本地实现，不代表必须跨框架移植；按工具决策可在源框架原生制作，或以其实现文件为骨架移植。`structure-study-only` 候选只能按该单一骨架重实现；只有所有候选均不合适，且逐项记录拒绝理由后，才允许自建。

ChatCut JSX 是落地载体，不是动效来源。复用/移植资产必须在描述和研究记录中绑定到一个具体镜头卡/实现文件；自建资产绑定自身源码与研究记录，不能用“参考了两个项目”代替来源说明。

## 旁白节拍与动作阶段

每个 B-roll 把已经批准的 `narration_beats` 原样落实到提示词实例的 `motion_sequence.beats`。数量、顺序、`at_ms` 与 `trigger_text` 必须一致；不能在制作时另起一套节奏。常见信息阶段包括：

1. 建立主体或共同问题；
2. 发生关系变化、比较、筛选、连接或展开；
3. 重点被确认或结果成立；
4. 如时长允许，保留一个可读的定格结果。

镜头不必机械凑四步；有效阶段数以旁白实际信息变化为准。入场淡化、背景循环、字幕出现、单纯镜头推拉和尾部阅读保持不算旁白节拍。生产完成后，每个 beat 必须有可定位的渲染资产与文件内时间点，并在主时间线审计中映射到实际 item 和 asset。

## 交付前检查

- 不看字幕，画面是否仍能读出关系或结论；
- 动画顺序是否跟随口播顺序；
- 是否连续重复、信息过载或长时间没有新信息；
- 当前结构是否来自本段语义，复用是否推进理解或帮助回顾，而非仅机械换字换色；
- 是否使用未经提供或无法核实的真实素材；
- 是否只使用一个最终来源；
- 是否落档了镜头卡、实现文件、许可证、当前资产和时间线实例；
- 是否实际预览了入场、变化中段和最终定格帧。
- `motion_sequence` 是否覆盖全部计划节拍，并且实际进入主时间线。
