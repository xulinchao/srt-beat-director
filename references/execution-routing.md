# 续做、工具切换与生产前检查

本页是操作入口；字段真源仍是 [contracts.md](contracts.md)，审核要求仍是 [qa.md](qa.md)。不新增第二套项目状态或授权台账。

## 1. 每次续做先定位

运行 `python scripts/check_workflow.py --project-dir <project> --action status`。用输出对照最近的用户范围、暂停/续做要求和已有批准：

- `config/project.json` 管规格、主工程、审核模式与批准引用；`planning_scope` 可提供任务说明，但自然语言不能由脚本自动判为授权。
- `planning/visual-plan.json` 管镜头、节拍与逐镜制作工具；DESIGN 管本片视觉规则。
- 实际文件和当前哈希证明资产存在；ChatCut 的实际读取结果证明项目、素材和 item 状态。配置里的 ID 本身不证明已经组装。
- 历史报告、预览网页、手写 workflow.md 是线索；与真源或实际结果冲突时先核对，不按文件日期自动选最新为正确。

只修复能从实际证据确定的差异：实际换工具则回写路由、重建可读视图并复核依赖；缺少用户批准不能自行补为 approved。已有确认明确对应当前版本时沿用，不让用户重复确认。暂停中的视频只做本次明确授权的维护或诊断。

## 2. 在动作前调用

```text
python scripts/check_workflow.py --project-dir <project> --action <action>
```

| 本次实际动作 | action 与额外参数 | 自动复用的主要检查 |
|---|---|---|
| 首次/变更方向的代表静帧、状态或单镜动态候选 | `baseline` | 计划已批准、输入/分镜/可读视图/规划提示词与审批绑定；不要求尚未产出的动态基线已批准 |
| 已批准方向的正式单镜资产 | `assets --shot S001 --tool hyperframes`（替换为真实 ID/主工具） | 计划和基线批准、实际工具与该镜路由相符、当前计划及 prepared 提示词/来源检查 |
| 组装/导出连续样片，或把镜头放入主工程 | `assemble --tool chatcut`（使用实际主工程） | 计划和基线批准、制作依据、主工程一致；ChatCut 还需已登记实际项目与时间线 ID |
| 扩大全片生产或正式整片导出 | `expand --tool chatcut` | 上述依据、有效样片批准及连续样片/动效参考检查 |
| 用户明确要求先看全时长候选 | `candidate --tool chatcut` | 同一主工程与内部连续样片检查；不要求伪造用户样片批准 |
| 审阅实际整片候选 | `delivery-review` | 当前状态、真实导出、提示词、逐镜时间线与交付证据 |
| 最终批准后交付 | `delivery-final` | 正式交付校验及当前审核模式下的有效批准 |

不传 action 默认只做 status。可选 `--out <path>/workflow-check-<label>.json` 保存派生报告；不写配置、审批、计划或生产实例。返回码 2 表示本次检查失败，0 仅表示所执行检查通过。

原有专项校验继续可用来定位失败；阶段入口调用同一实现，不维护另一套宽松标准。新任务的连续镜头门缺少真实样片会失败；旧任务的兼容提示不代表质量通过，扩大前仍须按 [sequence-quality.md](sequence-quality.md) 人工复核并按本次范围补真实证据。不要自动迁移历史批准或哈希。

`assets` 的 prepared 校验沿用现有全部计划实例检查；同批真源与依赖未变化时复用有效结果并逐镜核对路由，不每镜重复全量媒体校验。若只做局部修复，按原阶段的受影响范围检查，不为适配全量入口去重做无关资产或伪造缺失材料，并说明检查范围。

## 3. 子 Skill 只接收当前制作职责

调用 HyperFrames、Remotion、视频生成等工具前，把范围固定为“项目 / 镜头 ID / 旁白区间 / 预期动作 / 输出位置 / 返回主工程”。这些值直接取自现有计划，不另存一份同义计划。

- 单镜 `primary_tool` 是镜头最终视觉资产的制作工具，首尾帧出图等辅助链路仍按各自指引执行。
- 工具 Skill 的整片示例不改变本片主工程；不把完整旁白和所有镜头交给单镜工具合成整片。
- 工具返回后登记真实源文件、资产和失败信息，再继续父流程。实现失败按已声明回退处理；改工具先同步路由，不能事后只改报告声称一致。
- 真源、工具、设计或样片依赖变化使相应检查过期；同一批未变化部分复用。用户明确授权改变主工程时更新配置并重查受影响证据，不反复索要已有授权。

## 4. 检查之外仍须完成的工作

脚本不读取聊天授权、不检查在线工具可用性、不执行任意渲染命令，也不自动理解画面美感。调用生成工具前还要执行图片规则；组装前实际盘点目标工程；扩大前带原旁白看连续样片。输入检查通过不能代替这些动作。

典型恢复判断：

| 情境 | 应执行的下一步 |
|---|---|
| 静帧已获确认，用户说“继续” | 核对确认范围；准备动作验证，不能直接把基线写成已通过 |
| 单镜采用 HyperFrames，用户要完整版 | 单镜输出回到已选主工程；整片走 expand 或明确授权的 candidate |
| 旧 MP4 存在，计划仍 pending | 保留视频，核对版本与批准证据；不由文件存在推断通过 |
| 用户反馈 PPT 感和遮挡 | 回到具体动作/布局与连续样片验证；技术扫描正常不免除返工 |
| 只维护 Skill，原视频已暂停 | 修改本仓库并运行相应测试，不连接或恢复视频生产 |
