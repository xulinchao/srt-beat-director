# 视觉基线与镜头资产

适用：风格/状态候选、代表镜头动态验证、已批准方向的资产制作。入口和续做动作见 [SKILL.md](../SKILL.md)，操作前检查见 [执行检查](execution-routing.md)。

## 按当前镜头读取

- 实际提示词使用 [production-prompts.md](production-prompts.md)：人物三视图 §2（仅已有单张身份参考且需固定人物时）、A-roll §3/§5，固定人物视角加 §4，B-roll §6。实例与分区绑定命令见 [契约](contracts.md) §8；不修改旧实例哈希冒充重新执行。
- 新图片与编辑：[出图停止规则](image-generation-policy.md)。生成视频：[ComfyUI 视频](comfyui-video-production.md)。用户明确改用本地出图后才读 [本地图片](comfyui-image-production.md)。
- 工具选择：[逐镜选型](broll-runtime-selection.md)。只加载本镜选中的执行 Skill；HyperFrames 用 `hyperframes`，Remotion 用实际可用的制作技能。它们接收本镜范围，不能更换整片主工程。
- 连续镜头和参考检查：[sequence-quality.md](sequence-quality.md)；B-roll 骨架：[broll-production.md](broll-production.md)、[外部研究](broll-external-research.md)。

## 视觉基线

单张画风预览可提前交付，标记 `style-preview`；覆盖必要状态的静帧使用 `state-preview`；代表镜头带原旁白短片检查后才能使用 `motion-baseline`。交付候选时运行 `validate_visual_review.py`，批准视觉基线时同时检查技术结果与表达结果。文件和字段通过不代表画面通过；旧任务仅保留兼容提示，不自动改写审批或生产实例。

读取 [设计真源与角色互动](design-system.md)，使用 [DESIGN 模板](../templates/DESIGN.md)。已确认且适用的规范直接复用；新方向先以真实文案审阅代表 A/B、角色互动和高信息量镜头的开始/变化/结果，再完成带口播短片验证。设计、计划、选型和提示词绑定同一 design_ref，运行 validate_design.py；不预设账号最终画风，不把自检当用户确认。

建立视觉系统规范；有重复人物或用户要求的 IP 时再建立相应人物身份规范。确定构图安全区、B-roll UI token，并制作本片实际采用的典型画面。用户要求原创 IP 但没有参考图时，先按其设计要求用默认图片工具制作候选基准图，经过既有视觉基线审阅后才把选定版本登记为身份参考，不自行将候选图提升为身份真源。已有单张获准的人物身份参考、且需要规范化重复人物时才使用 `character-turnaround-v1`，保留 `prompts/character/` 实例；已有核实三视图不重复生成。普通重复人物的身份规范不等于用户要求设计 IP。对实际使用的重复人物逐项核对发色、发型、头身比例、服装和标志物。

人物身份与视觉系统分别记录参考范围、批准状态和哈希。只改信息卡、配色或动效不使人物身份自动失效；人物真源改变使依赖它的 A-roll 与角色参与的 B-roll 过期。计划和必要视觉基线通过后才新建 ChatCut 项目。

### 候选的范围与先后

视觉基线未批准时，只做验证方向必需的代表静帧和动态短片；候选制作不以“基线已批准”为前提，避免审批循环。先 `--action baseline` 检查计划与规划提示词，再读取本节对应生产提示词并保存代表镜头实例。`prepared` 对正式资产要求已批准 DESIGN，不将其当成生成首个风格候选的前提。用户只要求看静帧时交付候选，不记为动态通过。

代表镜头的独立动态短片用于验证动作；连接旁白、字幕和多个镜头的主样片由所选主工程组装。视觉基线通过后再建立完整 ChatCut 工程，边界见 [ChatCut 执行](chatcut-production.md)。

## 资产与动效

按对应章节保存 `prompts/a-scenes/<shot-id>.json`、`prompts/b-scenes/<shot-id>.json`，需要时派生 Markdown。进入镜头资产制作前运行 `validate_prompt_usage.py --stage prepared`。先生产人物/风格参考，再生成依赖它的 A-roll；无依赖的 B-roll 可并行准备。

A-roll 使用画面与动作序列提示词，固定人物再使用视角提示词。`action_sequence` 原样继承计划节拍，数量由语义决定，不按时长凑动作。单状态需计划 `static_reason` 并在实例中继承；多状态逐项保留资产或连续动画证据。以简洁人物处境为主，按语义选择视角、动作、景别和场景关系。

B-roll 使用 `motion_sequence` 原样继承计划节拍；生成场景保存工具与参考素材选择依据，程序化信息图复用编排阶段已通过的索引检查、选型、结构复用审查和研究记录；候选、输入或约束变化时才重新选择。已核实素材优先复用。合格模板具备预览、来源、明确动作阶段与质量批准；无合格模板按外部研究门选择唯一来源，记录许可证、原框架和兼容性，只做允许的最小适配。初轮候选不适合或目录为空时，都须按动作扩大搜索至参考仓库与未索引来源；仍无合适来源，再记录实际检查候选的拒绝理由和吸收的运动原则后自建。未声明许可证的公开代码只允许抽象结构研究。生产时不得把已批准的结构重新退化成通用列表、三卡或同构容器。

程序化镜头记录 `production.runtime_decision`；只有代码模板/动效实现层的新制作默认 HyperFrames，合格成熟效果可在原框架制作。Remotion 与 HyperFrames 按逐镜候选、表达、节拍和运行条件选用，不要求整片同时使用两者。需要生成连续场景动作或有用首尾帧约束的镜头，可按 [ComfyUI 视频资产生产](comfyui-video-production.md) 评估 MiniMax H3；其生成镜头沿用计划中的 A/B 职责并导入 ChatCut。有意设计的定格动画可使用状态序列，或在设计确需首尾帧生成时使用相应 H3 workflow；在 `motion_intent` 中写清跳变/连续运动的选择及原因。条件相近优先 HyperFrames，移植需具体依据。来源实现失败时回退到另一个已记录候选并重新确定唯一来源，不拼接多个骨架。仍失败则记录缺口，继续其他镜头；静态 SVG 只能是动画组件，不能冒充完成动效。

所有新图片与编辑（包括 IP 候选、三视图、A/B 状态图和视频首尾帧）先执行 [出图停止规则](image-generation-policy.md)；不可用时立即停整条工作流。若镜头选用 ComfyUI 连续动作，首尾状态图仍受同一出图门约束；从同一已核实身份/场景参考建立，优先由首帧编辑尾帧，检查人物、服装、背景、机位、画幅和计划动作的一致性。图片通过检查并登记后，才能作为 A-roll、B-roll 或视频首尾帧输入。

逐项记录提示词、模型、参数、版本、来源和校验结果。工具或选型变化回写计划、重生可读视图并复核受影响门控。

正式资产生产前用 `--action assets --shot <id> --tool <实际主工具>` 检查；这里的工具是最终镜头制作工具，首尾帧出图等辅助步骤仍遵守各自规则。工具变化先回写计划、同步 Markdown 并复核受影响审批。检查通过后才调用对应生成/渲染工具；回来先登记实际结果，再进入 [组装与交付](workflow-delivery.md)。

同一批生产中真源、提示词和依赖均未变化时可复用有效检查，不因逐镜操作重复全量媒体检查；每镜实际工具仍须与已检查路由一致。沉淀模板时才读 [模板库](template-library.md)，只认证实际渲染通过的模板。
