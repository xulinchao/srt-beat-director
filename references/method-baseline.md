# 方法基线

## 1. 项目内真源关系

本 Skill 发布后只依赖仓库内文件和当前任务输入：

1. `SKILL.md` 负责阶段路由、执行顺序和停止条件；
2. `references/production-prompts.md` 是各生产阶段直接使用的提示词真源；
3. `references/directing.md`、`contracts.md`、`broll-production.md` 与 `qa.md` 负责导演规则、数据结构、执行门控和验收；
4. 当前项目的 SRT、音频、参考素材、计划 JSON、提示词实例和生成资产构成任务真源。

不得依赖未随 Skill 发布的目录、视频或研究资料。`production-prompts.md` §1 是视觉编排阶段的执行提示词：必须生成 S001 连续编号、严格七列表头的可审阅表格，并在表格后列出素材缺口、待确认方向和高难镜头；表格通过前不得进入资产生成或 ChatCut 组装。本项目已有 SRT + MP3，以输入时间轴为真源，不在本流程内重新配音或重新对齐。

## 2. A-roll：讲人

A-roll 用人物 IP 建立“有人在对我说话”的感觉。它负责：

- 开场、章节过渡和总结；
- 经历、态度、情绪和个人表达；
- 把抽象语句变成具体小情境；
- 没有具体知识增量、但叙事上必须保留的内容。

固定人物模式可使用四种视角：

- `presenter`：正对镜头，中近景，适合开场、过渡、总结；
- `protagonist`：人物在环境中行动，适合经历、动作和情绪；
- `supporting`：配角成为焦点，补充主线情境；
- `first-person`：从 IP 眼睛看对象，画面通常只出现手脚或被观察物。

默认 A-roll 视觉基线是明亮、手绘、人物与环境完整、背景简化但能交代情境。人物存在不自动等于 A-roll：当人物只是知识图旁的讲解锚点时，画面仍属于 B-roll。

## 3. B-roll：讲内容

B-roll 负责知识和信息增量：概念、步骤、关系、比较、流程、数据、证据、界面和操作演示。

三种素材类型：

- `verified-media`（有素材）：用户提供或已核实的截图、录屏、图片、数据和案例；
- `diagram`（无素材）：用图形、卡片、路径、波形、流程和关系动画表达；
- `text-only`（纯文字）：章节、金句和结论，克制使用。

无素材和纯文字 B-roll 默认使用独立深色知识舞台；有素材 B-roll 保留网页、手机、文档或录屏的原色，并放在统一舞台和标注系统中。深色舞台是职责识别机制，不等于必须复制某个现成 UI。

## 4. B-roll 模板选择

每个 B-roll 先写清：观众要理解的一句话、素材类型、语义结构、信息项数量、可用时长和画幅。

选择顺序：

1. 匹配本地模板；
2. 没有合格匹配时，强制检查语义目录中的具体外部候选；
3. 至少读取候选镜头卡，`port-required` 候选还要读取对应实现文件；
4. 记录元素关系、主要动作、阶段顺序、语义适配和许可证；
5. 许可证允许复制时才移植源码，否则只根据抽象骨架重新实现；
6. 候选均不适合时，逐项记录拒绝理由和吸收的运动原则后才允许从零实现；
7. 按项目审核模式确认或自检候选骨架和视觉适配方案后再实现。

常用语义结构：`comparison`、`aggregation`、`filtering`、`hierarchy`、`causality`、`replacement`、`expansion`、`process`、`timeline`、`composition`。

## 5. 节奏与验收

- 镜头按完整语义切分，不按标点或固定秒数机械切换；
- A/B 自然交替，避免连续三四镜同类画面造成视觉疲劳；
- 同类连续时改变 A-roll 视角或 B-roll 结构，且必须有语义理由；
- 长镜头按口播安排有效信息变化，入场、呼吸、背景循环和字幕出现不算有效变化；
- 样片必须包含 A、B、一次完整切换、人物一致性和典型信息动效；
- 当前批准必须绑定最新真源哈希，旧样片不能证明新视觉系统通过。
