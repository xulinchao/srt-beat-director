# 方法基线

## 1. 项目内真源关系

本 Skill 发布后只依赖仓库内文件和当前任务输入：

1. `SKILL.md` 负责阶段路由、执行顺序和停止条件；
2. `references/production-prompts.md` 是各生产阶段直接使用的提示词真源；
3. `references/directing.md`、`contracts.md`、`broll-production.md` 与 `qa.md` 负责导演规则、数据结构、执行门控和验收；
4. 当前项目的 SRT、音频、参考素材、计划 JSON、提示词实例和生成资产构成任务真源。

不得依赖未随 Skill 发布的目录、视频或研究资料。`production-prompts.md` §1 是视觉编排阶段的执行提示词：必须生成 S001 连续编号、严格七列表头的可审阅表格，并在表格后列出素材缺口、待确认方向和高难镜头；表格通过前不得进入资产生成或 ChatCut 组装。本项目已有 SRT + MP3，以输入时间轴为真源，不在本流程内重新配音或重新对齐。

## 2. A-roll：讲人

A/B 是本项目内部的叙事职责标签，保留用于数据兼容，不是按全屏或有无人物分类。对用户使用具体表达名称；先按 [导演规则](directing.md#表达方式与元素选择) 选择表达，不能为满足类别比例增加镜头。

A-roll 用讲述者或人物处境承载叙事；是否需要固定 IP 由当前任务决定。它负责：

- 开场、章节过渡和总结；
- 经历、态度、情绪和个人表达；
- 把抽象语句变成具体小情境；
- 没有具体知识增量、但叙事上必须保留的内容。

固定人物模式可使用四种视角：

- `presenter`：正对镜头，中近景，适合开场、过渡、总结；
- `protagonist`：人物在环境中行动，适合经历、动作和情绪；
- `supporting`：配角成为焦点，补充主线情境；
- `first-person`：从 IP 眼睛看对象，画面通常只出现手脚或被观察物。

A-roll 画法与场景密度遵循当前 DESIGN；背景按讲述任务保留。人物存在不自动等于 A-roll：人物实际操作知识对象、帮助解释关系时，画面仍可属于 B-roll，不限于旁站讲解。

A-roll 以人物处境承载叙事，动作数量由语义节拍决定，不按秒数凑状态。单状态须说明静止为何足够；多个已计划状态必须全部落实。推镜、呼吸、眨眼与背景循环只能润饰，不能替代叙事变化。

所有有效变化先在视觉计划中绑定原始旁白 cue，再进入生产提示词和主时间线；不能在动画阶段另起一套凭感觉的时间点。A-roll 使用 `action_sequence`，B-roll 使用 `motion_sequence`，二者最终都回填同一份逐镜时间线审计。

## 3. B-roll：讲内容

B-roll 负责知识和信息增量：概念、步骤、关系、比较、流程、数据、证据、界面和操作演示。

三种 `material_type`（与表现形式分开）：

- `verified-media`（有素材）：用户提供或已核实的截图、录屏、图片、数据和案例；
- `no-material`（无素材）：用图形、卡片、路径、波形、流程和关系动画表达，`presentation_type=infographic`；生成式解释场景使用 `presentation_type=scene`，不得冒充真实证据；旧 `screen_subtype=diagram` 仅是实现类别；
- `text-only`（纯文字）：章节、金句和结论，克制使用。

B-roll 遵循与 A-roll 相同的 DESIGN；有素材画面保留原色。角色可以参与图解操作、承载和反应，不以人物存在与否区分 A/B。

## 4. B-roll 模板选择

每个 B-roll 先写清：观众要理解的一句话、素材类型、语义结构、信息项数量、可用时长和画幅。

再为这一段确定一个具体的 `visual_structure`。它描述观众实际看到的空间关系和阅读路径，例如文档组装、双栏进度、问题雷达、经历桥、判断天平、学习循环；“卡片”“列表”“深色 UI”过于笼统，不能作为结构名。全片可以统一配色、字体、材质、圆角和标注系统，同一核心图可以随语义递进，不靠机械换字换色替代解释。

B-roll 创意按 [表达选型](broll-expression-selection.md) 选择成熟表达借鉴或内容驱动设计；两者共存，均落实图片、讲解文字、人物职责、变化与阅读保持。程序化实现按 [production-prompts.md §6](production-prompts.md) 核对复用来源，无适配实现时研究后自建；该实现门不限制先设计内容关系。静帧按需核对构图与容量，多状态带原旁白检查运动，记录 layout_review。生成场景按动作、参考素材和工具能力选型，保持同一套旁白节拍与产物验收。工具决策见 [制作工具决策](broll-runtime-selection.md)；深度表达匹配见 [按视觉表达选型](broll-expression-selection.md)。

选型时对照最近三个 B-roll，审查复用的解释收益，不以重复本身否决；详见 SKILL.md「全流程保持的约束」。复用理由及用途写入 broll_structure_exceptions。

标准主语义结构只使用：`comparison`、`aggregation`、`filtering`、`hierarchy`、`causality`、`replacement`、`expansion`。流程、时间线和组成关系写入具体 `semantic_pattern` 或 `secondary_structures`，不新增主结构名称。

## 5. 节奏与验收

- 镜头按完整语义切分，不按标点或固定秒数机械切换；
- A/B 按语义安排，不固定交替节奏；连续三镜以上沿用既有理由记录与审核；
- 每个 B-roll 语义段使用与信息关系对应的具体视觉结构；复用是否合理由语义与实际画面判断，不以近三镜重复自动否决；
- 同类连续时复核视角、阅读路径与动作是否推进理解；递进与比较可保持同一核心图，不机械要求换结构；
- 长镜头按口播安排有效信息变化；新条目、名称和结论的建立可以有效，呼吸、背景循环和逐字字幕不能代替讲解；保留必要阅读时间；
- 样片覆盖实际主要表达方式、高风险动作与相邻接缝；出现重复人物时检查身份一致，不为凑 A/B 类别添加镜头；
- 当前批准必须绑定最新真源哈希，旧样片不能证明新视觉系统通过。
- 技术导出完成不等于最终批准。候选成片必须通过提示词生产证据、时间线节拍覆盖、QA、manifest 和文件哈希的闭环校验，手动审核仍需用户批准。
