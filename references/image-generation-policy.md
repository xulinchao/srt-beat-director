# 内置出图与全局停止规则

当前用户要求：出图必须使用内置 GPT；不能使用时，直接中断整个工作流并提示。该要求适用于新图片与图像编辑，包括人物候选、三视图、A/B 状态图、设计图和生成视频的首尾帧。

## 检查与停止

- 需要出图的生产任务，在视觉基线或任何资产生产前检查当前会话的内置 GPT 图片工具是否可调用；每次调用失败立即触发停止。纯分析、抽帧、维护 Skill 不调用出图，不因未验证图片能力而停止这些非生产任务。
- 用户要求的是内置 GPT 作图，不限定具体版本。使用当前可用的内置图片工具（例如 `image_gen`）；不因无法得知 2、2.5 等版本号而阻塞。实际模型名仅按工具返回记录，不猜测版本。旧 `gpt-image2` 标识保留兼容，不作为版本限制。
- 工具未暴露、权限/额度不足、限流、超时或出图失败时，立即停止整个视频生产流程；不自动重试、不调用备用图片工具，也不继续其他镜头、动画渲染、ChatCut 组装或导出。
- 已提交任务保留任务 ID 与输出，能安全暂停时暂停；不能撤销时如实说明，不提交新任务。保留所有已完成文件、提示词与错误，不清空工作区、不伪造成功记录。
- 在 `planning/image-generation-blocker.md` 记录：失败时间、当前阶段/镜头、所需能力、实际工具与可核实模型、错误或缺失证据、已完成产物、尚未结束的任务和恢复条件。镜头已有 `asset_status` 时按事实置为 `failed` 或 `gap` 并填写 `asset_gap`；不新增未经契约支持的项目状态值。

提示示例：

> 已中断整个视频工作流：本次需要内置 GPT 作图，但当前【工具不可用／实际错误】。已保留【产物路径】，未启动后续制作。恢复指定能力后可从【阶段/镜头】继续；如需改用其他工具，需要你明确更改本次出图要求。

## 恢复与边界

- 用户要求恢复后，重新核实指定能力并从断点继续；`continuous`、原计划中的备用工具、旧本地出图授权、H3 视频路由均不能覆盖此次停止规则。
- 只有用户另行明确更改本次出图要求，才允许改用其他模型/本地图片工具。把原话写入 `runtime_decision.user_request`，使用 `mode=user-request` 并记录原因，不能用 `fallback` 或 `capability-exception` 代替用户更改要求。
- ComfyUI 视频生成、已有合格资产的复用及普通裁切不是新出图；但一旦出图停止门触发，它们也不能绕过整条工作流的暂停。
- 旧 `gpt-image2` 记录及已生成本地资产保留历史真实性，不批量改名或伪造重新生成。恢复生产时按当前要求复核新调用。

## 校验范围

`validate_plan.py` 使用共享工具校验，拒绝以不可用/能力例外为由切换到已登记的非内置图片生成器，并要求显式用户更改原话；内置出图路由不能登记自动回退工具。普通裁切单独保留。校验器只检查计划，不探测在线工具，不负责取消运行中的任务；即时中断由执行代理按本规则落实，不能把计划校验通过说成出图可用。
