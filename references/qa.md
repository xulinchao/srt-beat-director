# 门控与验收

按本次交付阶段使用对应门控；已有检查绑定的输入和配置未变化时可复用，变更后重查受影响内容。分析、分镜、素材或局部修复不要求补做整片生产；完整成片仍须通过全部适用门控。

日常续做与生产前检查统一从 [execution-routing.md](execution-routing.md) 的 `check_workflow.py` 进入，专项命令用于对应阶段或定位失败。该入口复用现有检查，不替代本页的实际观看，也不自动更新批准。

审核模式沿用项目配置和本次用户授权。`manual` 在计划、视觉基线、候选方案、样片和最终成片的适用审阅点等待用户确认；`continuous` 只在用户已明确授权自检后继续时使用，完成同一检查并记录 `review_source=agent-qa-under-user-authorization`。已有授权不重复询问，代理自检不得写成用户确认；新增计费、账户、发布和系统权限仍按实际授权范围处理。

## 1. 预检门

需要出图的生产任务另按 [出图停止规则](image-generation-policy.md) 执行；预检脚本通过不证明在线图片能力可用。

阻塞项：

- SRT 或 MP3 不存在、不可读；
- SRT 无有效 cue、时间逆序、结束时间不大于开始时间或 cue 重叠；
- 最后一条字幕结束时间超过音频时长 250ms 以上；
- SRT 与音频明显不是同一内容，且无法安全判断应使用哪一份。

字幕间空隙不默认判错，但必须记录。预检脚本只验证结构和时长，不声称完成语义级音频转写核对。

分镜和交付校验均复核预检 status=pass、无阻塞项及当前 SRT/音频 SHA-256，并将报告 cue 列表与当前 SRT 实际解析结果比对。输入变更后重跑预检；旧报告缺输入哈希时不得复用。cue ID 唯一，每个语义段和镜头按原始 cue 顺序连续覆盖；原始 ID 数字有间隔可以保留，字幕空隙也可保留，但不能交错取 cue 或让相邻语义区间重叠。

## 2. 分镜门

先区分设计提案与可执行分镜。提案可以列出待比较方案；提交可执行分镜审阅前，逐镜对照 [表达决策](broll-expression-selection.md) 检查实际图片/物件、讲解文字原文、IP 职责、变化与保留、阅读保持及工具依据。关键项未决则保留草稿并说明缺口，不用字段齐全代替完成。该判断由实际审阅负责，当前结构脚本不自动判断语义覆盖或阅读效果。可读视图校验另逐列核对画面类型、设计、动态变化、衔接及工具依据与 JSON 一致；修改分镜须先更新真源，再重新生成表格，不能只改用户看到的说明。

- 每个 SRT cue 被且仅被一个镜头覆盖，不丢失、不重复；
- 镜头边界来自 SRT 边界，原字幕逐字保留；
- `planning/visual-plan.md` 存在严格的七列表头：`镜头 | 时间 | 配音文案 | 画面类型 | 画面设计 | 动态变化 | 画面衔接`；
- 镜头 ID 从 `S001` 连续递增，时间以毫秒呈现，表格后有素材、方向和高难镜头三个检查部分；
- 从 0ms 到音频结束的所有字幕外空隙都有明确保持策略，不出现未定义帧；
- 每镜都有 `viewer_takeaway`、A/B 职责、最终画面和至少一个有意义的变化或明确的静止理由；
- 运动方式与逐镜工具由计划绑定：`visual_design.motion_intent` 写清连续动作、定格状态序列、程序化动效或静止；`production.primary_tool` 写清该镜制作工具，并在计划 Markdown 的逐镜路由表展示。MiniMax H3 镜头的 A/B 职责须符合叙事用途，并有首尾帧/参考图、workflow 与运动提示证据；不得把未设计的素材卡顿解释为定格风格。
- A-roll 的状态数量服从语义，单状态有充分 static_reason，多状态覆盖全部计划节拍；通过 narration_beats 绑定原始旁白，不按时长凑动作；
- 每镜 `changes` 与 `narration_beats` 数量、顺序和毫秒点一致；每个 beat 的短语逐字来自其 `cue_ids`，时间等于首个 cue 起点；
- 列表、数字、引文和对应关系逐项盘点：每个必须上屏的信息单元有计划中的落点，`item_count` 与实际条目相符；省略项不会丢掉本段的理解目标。列表可作为语义需要的结构，不因反对通用列表而被省掉。
- B 画面需要真实素材时，来源已存在或被标记为素材请求；
- 每个 B-roll 都填写了具体 `visual_structure`，能说明空间关系、阅读路径和核心动作，而不是只写卡片、列表、信息图或深色 UI；
- 审查 B-roll 重复提醒及跨段核心图：记录 semantic_reason 与 visible_difference，后者可为内容推进或布局不变的回顾用途。复用有解释收益即可，不强制换结构；机械换字换色且无解释收益才拒绝。脚本 warning 不是自动批准，需人工核对；
- 继承用户已确认的 IP 与文字讲解需求；局部镜头让位不等于整片删除 IP。检查枚举是否逐项覆盖、图片展示是否有命名/定位、结果是否留够阅读时间；
- 全片只使用一种 A 画面生产模式；
- 没有为了 A/B 交替而破坏完整语义。
- 已按 [动作音效](sound-design.md) 判断关键动作的声音需要：适用时在动态变化和素材需求中标记，不要求每镜配声，也不增加旁白节拍。

视觉编排通过后记录当前真源文件的 SHA-256。会改变镜头内容、时间、A/B 职责或视觉系统的修改使批准失效。

### 维护时的表达回归案例

以下用于检查规则能否产生不同的合理表达，不是固定模板，也不代表已经渲染验证：

| 输入情形 | 应能设计的表达 | 应拒绝的退化 |
|---|---|---|
| 枚举五件物品 | 五项各有图片/名称与出现依据，随口播聚焦，前项保留，最后共览并阅读 | 只有“五件物品”标题，或五项一闪而过 |
| 材质、两罐构成、站蹲坐与胸前纹样 | 分别比较材质、拆合结构、展示姿态、定位纹样；真实图不足时声明示意与缺口 | 一张大图加推镜替代所有讲解，或套一段不对应的连续视频 |
| 屋脊、对面屋角与门外旷野 | 场景交代方位，再演示民俗想象；比较卡通状态动画与 H3，准确标注可用独立图层 | 方位不明、把信仰演成事实、因选 H3 删除讲解文字 |

再用一段适合自然动作的视频方案检查：允许直接选择 H3，不要求先试失败的代码动画；连续样片仍须验证身份、运动、停留与相邻镜头。三例均继承用户已确认的 IP 用法，并能说明哪些镜头出现、哪些让位。

## 3. 视觉基线门

新任务按 contracts §10 的 evidence-first-v1 检查候选。style-preview 允许先看一张画风；state-preview 必须覆盖该镜声明的必要状态；只有 motion-baseline 可进入视觉基线批准。运行 validate_visual_review.py，审批状态校验再次核对代表镜头、状态证据和实际动态短片。必要状态由动作决定，不机械要求每镜三张；安装、拆合等关系须包含实际需要验证的接触／连接，不能只摆完成图。

启用 DESIGN 的项目运行 `validate_design.py --stage prepared`，检查账号/单片引用、样张、字体文件、参数快照和真实审批证据。适用且已确认的规范直接复用；新方向先静帧、再带口播短片，按既有审核模式执行，不新增逐镜确认。检查通过只证明字段与文件一致，不代表实际画面合格。

- 人物或场景风格规范可以被后续镜头直接复用；
- 实际使用重复人物的身份参考时，三视图逐项匹配发色、发型、头身比例、服装和标志物；不得用“整体气质相似”替代身份核对。未要求 IP 时不得因模板需要补造固定 IP；已选择 IP 参与 B-roll 时也按逐镜解释收益决定是否出现；
- 典型 A 画面满足封闭构图，所有关键绘制痕迹在安全边界内；
- 典型 B 画面在目标画幅和样片时长内读得清；
- 按单片 DESIGN 叠加文字安全区、关键物件边界和字幕区辅助线；无既定值时先用文字四边 10%、关键物件 5% 检查。再分别检查视觉重心、共同对齐线、文字与所解释物件的归属；门联等附着文字还须在承载面内居中并留边。全部元素落在安全区内也不自动算布局通过。
- 主色、字体、线条、材质、光线、场景复杂度和字幕安全区已锁定；
- A 与 B 遵循同一 DESIGN，职责清楚；人物参与信息表达时布局、接触和遮挡准确，不预设明暗对比。
- 以真实素材比较主体笔触、明暗、材质、细节精度、主体比例、文字层级和留白；同底色不代表风格统一。检查卡片/框线/圈点的解释作用，内部制作说明和重复小字不默认进入画面；必要出处与示意身份保留。

## 4. 资产门

逐项检查：

- 人物身份、体型、服饰、比例和笔触是否一致；
- 交给 H3 的首尾关键帧是否使用一致的身份/场景依据，人物、服装、道具、背景、机位、画幅与计划动作是否衔接；定格状态图是否各自对应计划节拍和停留时长；
- 主体、动作对象和结果是否在静音状态下可读；
- 人物、道具、线条和符号是否完整，不触边、不被截断；
- 文字、数字和关系是否与口播一致；
- 列表逐项出现并最终共览，当前项明确、前项可回看、停留足够阅读；数字与单位、所指对象同屏可辨。只有标题或一句结论做了动效，不能代替这些内容的呈现。
- 真实素材有来源，生成素材有提示词、模型、参数和版本；
- 每个进入制作的 A-roll 与 B-roll 都有通过 `validate_prompt_usage.py --stage prepared` 的逐镜提示词实例；不能用“已阅读生产提示词”代替实际实例；
- 每个 A-roll 使用 a-roll-action-sequence-v1，落实全部语义状态和证据；单状态实例继承计划 static_reason。Slow Push、呼吸、眨眼和字幕不代替计划动作；
- 每个 B-roll 都有与视觉计划同序的 `motion_sequence`；模板默认动画时间不得替代旁白节拍；
- 新计划声明 broll_layout_policy=motion-first-v1，实例的 layout_review 按需记录关键状态、复用布局证据、原件可读性或有理由的静止。不能把静帧通过记成运动通过；多状态需实际带原旁白检查动态预览。旧记录未执行此门时明确兼容提醒，不伪造迁移。
- B-roll 资产保持计划中已批准的 `visual_structure`，没有在实现时退化为通用列表、三卡或同构容器；
- 目标画幅内无裁切、溢出或字幕区冲突。
- 起始、逐项出现、最终共览三类关键帧的文字/主体边界可读且归属清楚；列表行、数字与单位、证据原件与解释均有稳定对齐，不能用放大留白或缩小字体掩盖结构问题。短标签按目标观看尺寸核对，须贴近所指物件且一眼能读；截图缩小后几乎消失的“左联/右联”一类注释不得视为已解释关系。
- `no-material + infographic` B-roll 在没有合格本地模板时，已确认的参考仓库来源有通过校验的 `reference_confirmation`；外部来源与自建有通过校验的 `planning/broll-research/<shot-id>.json`。召回分数和候选列表本身不构成确认；
- 外部候选落实到具体镜头卡和实现文件；选择自建时，每个候选都有拒绝理由和可追溯的运动原则；
- 新程序化 B-roll 使用 expression-first-v1，选中来源有实际预览证据；自建有按动作扩大查询的 expanded_search，不以目录为空、题材不同或否决两个粗分类候选放行。研究校验不能证明实际搜索/观看发生，继续核对工具结果与证据。
- 检索报告明确区分标签、词汇与真实向量命中；未启用向量不宣称语义模型已工作。核对 constraint_fit 中的冲突和未知项，特别是内容/载体是否保持、前项是否保留、末态是否共览、出处是否连续；融合排名不构成适配批准。
- 静态 SVG 只作为动画组件使用，不单独充当已完成 B-roll；动效须有可审阅预览和实际渲染结果。本地认证模板与外部研究骨架至少有三个阶段；镜头的实际信息节拍按批准的 `narration_beats` 验收，不机械补足数量。

失败资产标记为 `stale` 或 `rejected`。通过文件哈希复用，不因布局或文字微调重新生成。

## 5. 动效与混合样片门

新任务额外执行[连续镜头质量门](sequence-quality.md)：用相邻镜头带原旁白正常速度连看，记录运动中间态、接缝、实际解释收益与整体PPT感。缺证据或任一结论未通过时先修复受影响设计，再运行expand校验，不扩大制作。内部自检不自动变成manual批准；用户明确要求完整候选时也执行相同内部质量检查。

新检查记录把 technical_review 与 expression_review 分开。文件可读、哈希、视频流、时间点等技术检查通过，不能覆盖表达失败；按计划核对实际行动、结果、旁白同步并记录观察。新任务 produced 逐镜检查 motion_review，包括一个旁白节拍内的多个必要状态。脚本核验记录与媒体，不自动识别动画的因果意义；表达判断仍须真实观看、试听及有效审核来源。数据契约和命令见 contracts §10。

对承担解释或叙事的动作，在已有逐镜 QA 中分别记录技术结果与表达结果，并引用实际资产和时间点：行动是否发生、对象是否按计划回应、可见后果是否表达原意、关键变化是否对应旁白、结束保持是否足够理解。先静音看关系，再带原旁白看同步；静音不要求替代所有旁白信息。只摆出终态、只有抖动/推镜、计划需要的关键接触缺失或动画演出错误因果，均不能冒充计划动作完成。提示词与静帧不能证明连续动作通过。

准备、行动、反作用和保持是候选设计方法，不作为固定数量的验收项；有理由的静止、无人物图解和刻意跳变仍按原规则检查。只有当前输入与实际片段通过检查后，才能把该案例登记为可复用；适用边界与失败原因一并保留，不把三条实验的通过推广成所有文案或所有模型均有效。

专项验证分别回答：表达选得是否合适、动作设计是否准确、实际制作是否实现。验证 IP 互动讲解时，必须包含人物参与知识关系的实际片段；人物叙事或历史场景动作通过不能替代此项。可与无人物方案比较解释收益，不强制每镜制作两版。记录真实输入、预期、实际结果与失败边界；文档或校验通过只证明规则和记录，不证明视频效果。用户要求独立新任务验证时，通过初始化脚本建立新工作区，使用当前规则与真实旁白，不沿用旧项目审批或将旧片段作为新验证结果。

角色互动样片检查：对象按旁白出现，需要接触时落点与停留符合计划，锚点和遮挡正确，角色反应与对象协调；高信息量下人物让位，文字和字幕可读，A/B 连续衔接一致。按实际文案选择进度标记、信息展示、密集布局等代表案例，不为凑测试改文案。换文案后重查容量、换行、阅读时间和实际字体载入。

混合人物与文字时，先按观众的主要理解任务核对 A/B，再检查次要元素的操作、导航、标注或叙事关系；不因有人物、有卡片或没有物理接触直接否决。有关联仍须通过可读性、遮挡和节拍检查。A-roll 使用连续视频时按实际连续动作验收，不强制改成状态图；精确文字与图形由独立排版/合成落实，检查与人物视频的实际接触、遮挡及同步。

程序化镜头的 `production.runtime_decision` 必须通过计划校验，选择依据能定位预览、源码或诊断记录。若全片混用 HyperFrames 与 Remotion，样片应包含两者实际渲染结果，核对统一规格、视觉风格、正常播放速度和接缝。只选一种框架时不要求额外制作另一种。

样片覆盖本片实际采用的主要表达方式、相邻衔接、重复元素一致性与高风险动作；计划同时使用 A/B 时覆盖两者及切换，不为凑类型增加镜头。局部验证按用户指定范围检查，不冒充整片样片验收。计划校验仍可能提示样片未同时包含 A/B；按实际计划核对并记录理由，不为消除这条提醒增加无用镜头。检查：

- 任意定位到镜头开始、中点和结束附近，画面状态可正确恢复；
- 生成式连续动作检查首尾落点、中途身份漂移、背景/道具变形、动作断裂、重复帧和意外闪变；定格动画检查计划内的停留与跳变节奏，刻意跳变不按连续动作的流畅度判失败，额外丢帧或人物无故变化仍须修复；
- 动画严格跟随口播顺序，没有依赖实时随机数或播放历史；
- 没有元素重叠、越界、闪帧、错误字体、错误文字或不可读阶段；
- 外部字幕安全区始终可用；
- 长镜头的变化或有理由的保持服务于理解，短镜头没有被压缩到读不清；
- 音画节奏和切换方式可代表全片。
- 带原旁白试听计划中的动作音效：有效起音对齐接触、启动或落定帧，轻重和材质符合画面，不遮住关键词；无密集堆声、重复源声音、削波失真或裁切爆音。未试听不得记为声音验收通过。
- 按 B-roll 出现顺序连看时，空间关系、阅读路径和核心动作有足够变化；统一视觉系统没有造成模板复印感或视觉疲劳。
- 对照已认可基线检查素材画法与文字层级，并核对关键词、数字、分组、替换的实际理解收益、动作速度/重量/停顿和结果保持；连续自建先复核搜索与适配过程，再决定是否扩大制作。出现粗糙线稿、无用框线小字或用户禁用的 SVG 表达时返工受影响镜头，不靠更多淡入或下划线补救。

`review_mode=manual` 时，用户确认样片后记录样片文件、视觉计划和视觉基线的哈希。`review_mode=continuous` 时，代理完成同一组检查、修复并记录 `review_source=agent-qa-under-user-authorization` 后继续；不得写成“用户已确认”。任一关键真源变化后，样片状态变为 `stale`。

样片完成 QA 后、记录批准前，创建当前依赖快照：

```text
python scripts/sample_dependencies.py --project-dir <project> --sample preview/sample.mp4 --out <project>/preview/sample-dependencies-v2.json
```

把快照的项目相对路径和输出 SHA-256 写入 `approvals.sample.dependencies`，并按真实审核来源记录样片批准，再运行 `python scripts/validate_state.py --project-dir <project> --out-dir <project>/planning`。快照命令不写审批，不代表审核通过。新快照使用 2.0 分区依赖及新文件名；区间外镜头修改仍复核全片计划，但未受影响的样片无需重复批准。旧 1.0 保持原校验，不自动迁移；字段见 [contracts.md](contracts.md) §9。已批准旧样片缺少快照时不能继续声称依赖有效：先标 stale，复核受影响内容，再建立新的审批证据；不自动修改历史记录。历史 QA 报告若绑定已作废视觉基线，只能保留为历史证据。

## 6. 最终门

启用`sequence_review_policy=sequence-quality-v1`时，`sequence_review.full`须绑定本次成片并覆盖全片；review与final交付都复核该证据。字段见[契约 §11](contracts.md#11-连续镜头质量门)，自动检查的能力边界见[连续镜头质量门](sequence-quality.md)。

先审实际结果：画面是否表达原文、计划动作是否落实且跟随旁白、视觉是否符合本片 DESIGN、素材是否真正进入主时间线。字段、提示词和校验报告证明流程记录完整，不能代替实际画面与声音的判断；不以用了多少工具或同时使用几种框架作为完成标准。

- 使用最新已确认的视觉计划、视觉基线和样片版本；
- 实际使用的框架按其工具规范通过结构、渲染与视觉检查；HyperFrames 运行对应 lint/check，Remotion 运行项目检查并验证实际渲染与抽帧；
- 音频结束、时间轴结束和视频结束的误差不超过 `max(1 帧, 50ms)`；
- 总时长、总帧数和音频哈希一致不证明同步正确。必须按计划核对每个镜头起止位置、内部旁白节拍及对应字幕，并抽查前中后段实际导出画面；发现后段画面提前、前段延迟或末帧长时间冻结时，判为时间映射失败。时间映射失败不得只补黑帧后交付，应从原始旁白、SRT 和逐镜准确帧区间重建，并说明采用的实际导出路径。
- 开头、镜头间空隙和尾部均保持预期画面，无黑帧、闪回或意外重置；
- 对实际导出的完整视频逐帧解码，扫描单帧黑闪、短黑段和相邻帧突变；不能用编辑器预览正常、导出任务成功或首中尾抽帧代替。记录被检查文件的路径、SHA-256、帧率、解码帧数、异常帧号及时间。深色背景和正常切镜只是候选，须查看异常帧及前后帧确认；未经解释的异常不得通过。
- 异常按源素材时间、时间线位置、导出帧三层核对，考虑裁切、变速与帧率。源素材正常而导出出现异常时，保留失败文件并用新文件名重导对照；重导后异常位置移动也必须重新全片扫描，不能沿用旧黑帧列表。无日志或对照证据时不把原因断言为 GPU、缓存或某个渲染框架。
- 如采用成片补帧修复，仅处理已逐帧确认、前后画面稳定且无动作或字幕变化的孤立坏帧，保持原时间戳、总帧数和音频；连续坏段、切镜或动作阶段应回到源资产/时间线重渲染。报告明确区分“成片已修复”与“导出器根因已修复”，保留原片和修复映射。修复后重新扫描全片并复核音画同步。
- 对每个镜头至少检查开始、中点和结束附近的稳定帧；对转场另检查前后接缝；
- 对转场再看实际混合中间帧与正常速度播放：没有双重文字、错误的证据叠合、人物残影、突兀的空白闪或意外闪烁；下一句有效信息开口前，新镜头已落稳。加转场仍须保留原旁白、字幕和镜头边界的时间映射。
- 无人物漂移、构图破坏、文字错误、遮挡、裁切、溢出和不可控随机变化；
- 按镜头已记录的运动意图复核最终时间线：连续镜头没有不自然断裂；定格镜头的跳变与停留符合计划且没有意外缺帧；程序化信息动效的顺序、阅读时间和旁白节拍一致。
- 所有缺失素材、保留意见和已知限制在 QA 报告中明确列出；
- 实际导出已按 [动作音效](sound-design.md) 回放核对：计划音效已落实或明确记录缺口，旁白清楚，同步和混音正常。文件含音轨、峰值检测或编辑器试听不能代替实际导出的听感验收；变更动作、混音或重新导出后复查受影响声音。
- `manifest.json` 能定位并校验全部输入、真源、资产、工程、报告和最终 MP4。
- 按契约 §7 核验非空 manifest.files，并比对独立时间线快照与原始工程读取结果：实例 ID、素材 ID、源文件哈希、实际帧范围、裁切和速度均一致；连续素材证据时间在实际时长内且满足源时间映射。HyperFrames/Remotion 镜头保留 production.source_files。缺少这些证据时阻塞此次交付，不自动重写旧审批。
- `validate_prompt_usage.py --stage produced` 通过；旧实例绑定当前生产提示词整文件 SHA-256，新 per-prompt-v1 实例保留执行时原文副本并匹配当前所用章节与共用规则，均能定位实际输出。
- A-roll 的每个动作节拍都能定位到不同状态资产，或同一连续动画中的不同证据时间点；计划多个状态但成片只使用单张图时不得通过。
- B-roll 的每个信息节拍都能定位到渲染资产中的不同状态时间点，并映射到主时间线素材实例；模板选择报告或终态截图不能作为成片证据。
- 全片 B-roll 结构审计与实际成片一致：合理递进、比较和回顾允许复用；不存在无解释收益的机械重复。另核对人物处境、必要道具、目标观看尺寸下的表情可读性，以及读书稿作者原话、转述、个人理解与实践的归属；

ChatCut 主时间线路径另检查：

- 活动项目 ID 与 `config/project.json` 一致；
- 成片使用保留原版本后的明确时间线，时间线 ID 已记录；
- `visual-plan.json` 中每个镜头都能映射到实际时间线素材实例和准确时间范围；
- 标为 B-roll 的镜头确实使用图解、动效、截图、录屏或信息文字，不由装饰性 A-roll 静态图占位；
- HyperFrames / Remotion 渲染结果已成为 ChatCut 素材并实际放置，而不是只存在于本地目录；
- 最终 MP4 由 ChatCut Desktop 导出，且导出文件存在、非空、时长合理。

最终交付至少包含：最终 MP4、`qa-report.json/.md` 和 `manifest.json`。使用 HyperFrames 或 Remotion 时保留各自源工程和渲染文件；使用 ChatCut 时另保留 `timeline-audit.json/.md`。关键动作按需配简单音效，并记录素材与实际试听结果。除非用户明确要求，不烧录字幕，不添加 BGM、复杂声音设计或非必要 3D 动画；用户要求无音效时优先执行。

## 7. 交付闭环

每次实际导出后，先扫描该文件：

```text
python scripts/scan_video.py --video <project>/render/final.mp4 --out <project>/reports/frame-scan-v1.json
```

扫描会完整解码每一帧，以 160×90 灰度缩图检测黑帧候选和相邻帧大幅变化；这是候选检测，不是视觉质量判断，小面积闪烁仍需逐镜视觉检查。报告使用零起点帧号；时间按固定帧率计算，成片须符合项目的固定帧率。检查候选的原分辨率前后帧，正常暗场或切镜在 `review` 中记录接受理由和证据；坏帧修复后对新文件重扫。不得删除候选列表代替复核。扫描完成的退出码 0 只表示检测完成，不代表候选已接受。

复核后将扫描报告路径与最终 SHA-256 写入 `qa-report.frame_scan`；字段见契约 §9。然后完成逐镜检查和 §6 的提示词生产证据校验，运行：

```text
python scripts/validate_delivery.py \
  --project-dir <project> \
  --production-prompts references/production-prompts.md \
  --mode review \
  --out-dir <project>/reports
```

`review` 模式检查当前状态依赖、实际视频流和解码帧数、扫描证据、提示词证据、时间线帧范围及交付对象一致性；不代替画面和声音的实际审阅。需要 PATH 中可用的 ffprobe；扫描另需 ffmpeg。缺失工具、探测失败或证据过期均阻止交付，不退回仅核对 JSON。`manual` 下保持 `status.final=rendered-pending-user-review`，等待用户批准；`continuous` 下由获授权的代理完成最终 QA。实际批准后写入 `approvals.final`（当前成片哈希、时间和真实审核来源），设置 `status.final=approved`，再用 `--mode final` 验证；只有通过后才可称为最终批准交付。
